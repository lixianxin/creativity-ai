【商业模式分析报告】

一、商业模式概述  
- 模式类型：B2B（学校机构采购）+ B2C免费触点（学生为使用者，非付费方）  
- 核心价值交换：高校创业学院/教务处支付年费，获得一套可嵌入教学与评审流程的AI评审系统；学生作为终端使用者免费获得模拟评审反馈；项目方通过API调用成本可控地交付标准化SaaS服务。  
- 商业闭环：学校有评审提效与过程留痕需求 → 采购机构版 → 系统部署/接入教务流程 → 学生提交想法 → AI委员生成结构化评审报告 → 教师使用报告开展教学或筛选项目 → 项目方按年收取授权费 → 若报告质量稳定、教师依赖该工具完成关键教学动作，则触发续费。当前闭环中“教师是否真实依赖该报告替代/补充人工评审”“是否纳入正式教学考核流程”“续费决策机制是否明确”均无实证，首单后复购链未建立。

二、角色关系  
- 使用者：高校创新创业学生（提交想法、接收反馈）  
- 付费方：高校创业学院或教务处（预算来自教学经费/双创专项经费）  
- 决策者（谁决定付钱）：院系分管副院长、教务处负责人、或双创教育主管（非一线教师；需对教学成效、流程合规性、资源投入产出负责）  
- 服务提供方/供给方：本项目团队（基于大模型API构建并运维AI评审系统）  
- 平台角色：非双边平台，是B2B SaaS工具提供商；不连接供需双方，不撮合交易，不承载学生与外部资源（如投资人、导师）交互；其核心角色是“将模糊的评审经验结构化、可复现、可归档”的教学支持基础设施。

三、价值主张  
- 对使用者（学生）：免费获得接近真实创投语境的多维度反馈（市场、技术、团队、财务等），提升商业思维与BP撰写能力；降低“想法无人反馈”的挫败感。  
- 对付费方（学校）：降低人工评审组织成本（时间、专家协调、标准化难度）；生成可追溯、可分析、可沉淀的评审数据，支撑教学评估与项目孵化决策；强化双创教育数字化形象。  
- 对供给方/合作方：无外部合作方；大模型API供应商仅为成本项，不参与价值分配，亦不构成价值主张主体。

四、付费逻辑  
- 谁付钱：高校创业学院或教务处（公款采购主体）  
- 为什么付（买到的具体价值）：购买的是“可嵌入现有教学管理流程的、符合高校语境的AI评审能力”，具体包括：① 符合教学目标的反馈维度（非纯VC逻辑）；② 与校内系统（如教务平台、学工系统）对接能力；③ 报告格式/术语适配教师使用习惯；④ 数据归属与隐私合规保障（学生数据不出校）。  
- 什么场景下付（付费触发点）：新学期开课前完成采购部署；或配合年度双创项目遴选周期（如每年3–4月集中申报期）上线使用；触发前提是系统被确认为“教学必需环节”，而非辅助玩具。  
- 付费假设是否有证据：付费假设待验证。目前仅有2位老师“口头表示感兴趣”，未出现：① 明确预算来源说明；② 采购流程启动（如立项、比选意向、试用申请）；③ 对数据主权、系统对接、报告权责等关键采购条款的实质性讨论。口头兴趣 ≠ 采购意愿。

六、商业交易链  
用户需求 → 价值提供 → 交易发生 → 项目方获得收入 → 用户获得持续价值  
高校需提升双创项目初筛效率与教学反馈质量 → 项目方提供AI评审系统（功能已实现，但未验证是否匹配高校教学动线） → **尚未发生真实交易**（无合同、无付款、无部署） → 项目方尚未获得任何收入 → 教师未在真实教学场景中持续使用该系统，学生反馈未形成教学闭环，续费无依据。  
【商业闭环断点】：交易发生环节缺失；项目方未进入“交付→使用→验证→续费”链条，首单尚未闭合。

七、获客与转化逻辑  
- 用户从哪里来：高校内部——学生通过课程作业、双创训练营、校内通知接触系统；教师通过同行交流、教育技术展会、AI教育类社群获知。  
- 如何认识产品：目前依赖创始人个人关系或教师自发传播；无标准化触达路径（如未接入教育部双创平台、未与省级教指委合作、无院校白皮书案例）。  
- 为什么尝试：教师希望缓解评审人力压力，或探索AI教学创新；学生因课程强制要求或好奇尝试。  
- 为什么第一次付费：**尚未发生**；需证明该系统能替代/显著增强现有流程（如：原需5名导师耗3天完成100份BP初筛，现系统2小时内输出结构化报告+TOP20推荐清单，并被教师采纳为筛选依据）。  
- 为什么继续使用/复购：取决于报告是否被纳入教学SOP（如：BP修改必须基于AI报告批注；结课成绩部分依据AI反馈完成度）；目前无任何机制绑定使用深度与教学成果。

八、商业模式风险  
- 付费意愿风险：高校采购强调“必要性”与“合规性”，非“新颖性”。若系统仅提供“更酷的反馈”，而非“不可替代的教学交付物”，则难以立项。  
- 付费方识别风险：误将一线教师（使用者/推荐者）等同于付费方；实际决策者是掌握经费审批权的行政负责人，其关注点在于风险控制、流程留痕、跨部门协同成本，而非学生体验。  
- 转化风险：从“老师感兴趣”到“院系立项采购”存在高门槛（需写可行性报告、过采购会、签合同、走财政支付流程），当前无任何环节落地。  
- 平台依赖风险：无；本模式不依赖第三方平台，属自主交付型SaaS。  
- 去中介化风险：低；不存在双边供需，无绕开可能。  
- 免费替代风险：高；教师可用ChatGPT+提示词模板完成类似反馈；若本系统未建立“高校专属知识库”（如本地产业政策库、往届获奖BP范式、本校评分细则），则价值护城河极弱。

九、关键商业假设  
1. 高校创业教育场景中，存在对“结构化、可归档、教学对齐”的AI评审能力的真实采购需求（而非仅技术尝鲜）。  
2. 项目方能将通用大模型能力转化为符合高校行政与教学双重要求的交付物（含数据主权设计、系统对接能力、报告权责界定）。  
3. 首单客户愿意以“最小可行采购”（如单学期试用、限定班级规模）启动合作，而非要求全量覆盖、等保三级、定制开发等高门槛条件。

十、最小商业验证  
- 验证对象：高校是否愿为AI评审系统支付首笔费用（哪怕1元），并完成合同签署与部署。  
- 验证方式：向2所已表达兴趣的学校发起正式试用邀约，附《教学嵌入方案》（明确如何接入1门课程/1次遴选）+《数据与权责说明》+《1万元以内快速签约通道》；要求对方签署试用确认函并预付象征性定金（如1000元）或出具加盖院章的试用备案说明。  
- 核心观察：是否愿意启动采购流程（而非仅试用账号）；是否提出数据不出校、报告需嵌入校内系统等刚性条款；是否指定行政接口人（非教师个人）。  
- 通过条件：至少1所学校完成定金支付或盖章备案，并明确下一阶段采购节点（如6周内召开采购会）。
