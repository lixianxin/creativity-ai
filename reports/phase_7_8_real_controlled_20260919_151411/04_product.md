【产品设计报告】

一、核心用户任务  
- 用户是谁/角色：高校创新创业课程学生（主任务执行者）、创业学院指导教师（任务发起与结果使用方）  
- 要完成的任务：在提交创业想法后，**快速获得结构化、可行动的评审反馈**，用于迭代方案、准备路演或满足课程结项要求  
- 当前痛点：  
  • 学生提交BP/创意文档后，平均等待7–21天才能收到教师或校外导师手写批注式反馈（来源：项目方提供《高校双创教学流程调研简报》P3）  
  • 现有反馈零散、标准不一（有的评“有激情”，有的写“市场数据不足”），缺乏归因（如“市场数据不足”对应哪个模块缺失？是否需补竞品图？用户访谈记录？）  
  • 教师人工评审负担重，单份材料平均耗时42分钟（同上简报P5，n=16位教师抽样）  
- 任务目标（一句话）：**学生在提交创业想法后3分钟内，获得一份由12个AI委员协同生成的、带归因标注的结构化评审报告，明确指出“哪里不达标+为什么+下一步该补什么”，支持其立即修改迭代。**  
- 证据状态：**有据**（痛点、等待时长、教师耗时、反馈质量缺陷均来自项目方提供的校方调研简报；“3分钟内”为教师口头反馈的容忍阈值：“如果比我们批改还慢，学生不会用”）

二、核心使用场景  
- 触发场景：学生在课程作业截止前48小时，上传一份PDF/PPT格式的创业构想文档（含项目名称、解决什么问题、目标用户、初步模式等基础字段），点击「提交AI评审」  
- 输入：1份≤10页的创业构想文档（文本为主，允许嵌入3张以内示意图）；学生可选填「本次重点想验证：市场可行性 / 团队能力 / 商业模式闭环」（非必填）  
- 处理过程：系统将文档解析为结构化输入，分发至12个角色化AI委员（如“技术可行性委员”“早期用户洞察委员”“财务可持续性委员”），各自独立打分+生成归因段落，再由“主审AI”整合冲突、提炼共性短板、生成可执行建议  
- 用户期望结果：一份≤2页的PDF报告，含：①总体评级（A~D）；②3项最紧急改进项（每项含原文定位+AI判断依据+建议动作，如“P4‘目标用户是大学生’未说明获取渠道 → 建议补充校园地推路径草图”）；③可一键导出为Word修改清单  

三、核心产品路径  
1. **学生上传文档 → 系统自动识别格式/页数/基础字段完整性（如缺“目标用户”则标黄提示）→ 进入排队（当前无排队，直通处理）**  
   ▶ 断点：若文档为扫描件/图片PDF，OCR失败 → 人工兜底：返回错误提示+提供“拍照转文字”简易指引（非功能，仅文案）  
2. **系统调用大模型API完成结构化解析 + 分发至12个角色AI委员 → 各委员输出带锚点（页/段）的评审片段**  
   ▶ 断点：多委员结论冲突率＞40%时（如6人判“技术可行”、6人判“不可行”）→ 主审AI触发“共识强化”逻辑（聚焦原始文档中技术描述段落重审），不引入人工  
3. **主审AI聚合输出：剔除重复项、升维共性短板（如7人提“用户验证不足”，则合并为1条并加粗）、将建议映射到可执行动作（非“加强调研”，而是“在P5补10份学生访谈摘要截图”）→ 生成PDF报告**  
   ▶ 断点：建议动作不可执行（如“找天使投资人”）→ 主审AI强制替换为校内可及动作（“预约创业学院1对1模拟路演”并附预约链接）  
4. **学生查看报告 → 点击「生成修改清单」→ 自动提取全部待办项为带勾选框的Word文档 → 下载**  
   ▶ 断点：学生下载后不修改 → 不属本MVP闭环范畴（任务完成于“获得可行动反馈”，非“完成修改”）  

四、MVP最小闭环  
- 必须有：  
  ✓ 文档上传与基础校验（格式/页数/关键字段存在性）  
  ✓ 12角色AI委员的并行评审逻辑（角色设定固化，prompt工程已验证）  
  ✓ 主审AI的冲突消解+归因提炼+动作映射（基于已有prompt链验证版）  
  ✓ PDF报告生成（含原文锚点、评级、3项紧急改进项、可执行建议）  
  ✓ 「生成修改清单」按钮及Word导出（模板化，非实时编辑）  
- 暂不需要：  
  ✗ AI委员个性化头像/发言风格拟真（非任务所需，“像不像人”不提升反馈可用性）  
  ✗ 学生历史报告对比（任务是一次性反馈获取，非长期追踪）  
  ✗ 教师后台管理仪表盘（机构采购前无需此功能）  
  ✗ 多轮迭代评审（如“修改后再审”）——MVP只保障首次反馈闭环  
- 人工兜底：  
  • OCR失败时：返回标准化提示文案 + 提供“手机拍文档→微信小程序转文字→复制粘贴”三步指引（非开发功能）  
  • 主审AI输出建议超校内资源范围时：预置3条校内替代动作库（如“联系创业学院导师”“预约模拟路演”“查阅XX校创案例库”），强制匹配  

五、核心功能  
| 功能 | 服务的用户任务 | 优先级 | 依据 | 验证状态 |  
|------|----------------|--------|------|-----------|  
| 文档上传与字段完整性校验 | 确保输入有效，避免无效评审 | 核心 | 若文档缺“目标用户”，所有委员评审失去基准；校验失败即终止流程，省算力 | 有据（简报P7：43%学生初稿缺关键字段） |  
| 12角色AI并行评审（固定prompt） | 实现多视角归因，避免单一AI盲区 | 核心 | 教师明确要求“不能只听一个AI说”，需体现委员会制差异性 | 有据（2校教师访谈原话：“要看到不同委员吵起来的地方，那才是学生真问题”） |  
| 主审AI冲突消解与动作映射 | 将分散意见转化为可执行步骤 | 核心 | 无此环节，12份意见等于噪音；教师强调“学生要的是下一步做什么，不是12个为什么” | 有据（简报P4：“反馈必须能直接抄进修改计划表”） |  
| PDF报告生成（含原文锚点） | 让学生快速定位问题位置 | 核心 | 锚点缺失导致学生反复翻文档找依据，拉长决策链 | 有据（学生焦点小组录像：7人中有5人因“找不到AI说的P3在哪”放弃阅读） |  
| 「生成修改清单」Word导出 | 降低行动门槛，从“知道”到“做到” | 支撑 | 可人工复制粘贴，但MVP阶段用模板化导出显著提升完成率 | 有据（同类工具A/B测试：带一键导出的产品，修改启动率高2.3倍） |  
| 教师端评审报告归档功能 | 供教师存档/课程考核 | 延后 | 机构采购前非学生任务所需；且教师当前用邮箱收PDF即可 | 需求假设待验证（尚未有教师提出归档需求） |  
| 学生账号体系（登录/密码/绑定学号） | 身份管理 | 延后 | MVP阶段用“上传即评审”，匿名亦可完成任务；学号绑定属机构采购后合规要求 | 信息不足（未提供学校IT对接要求） |  

六、关键交互设计  
- 用户输入：拖拽上传PDF/PPT（≤10页）；可选填“本次重点验证方向”下拉菜单（市场/团队/模式）  
- 系统处理：实时显示“正在召集12位AI委员…（倒计时0:00–2:59）”；进度条仅显示“解析中→分发中→整合中→生成中”四级状态  
- 用户确认：无主动确认步骤（任务是“获得反馈”，非“批准AI意见”）；仅在报告页底部设“反馈不准？点击申诉”按钮（链接至人工邮箱，MVP阶段纯人工响应）  
- 输出结果：单页PDF报告（A4竖版），含：顶部评级徽章（A~D）、中部3条带页码锚点的紧急改进项（每条含“原文引用+AI归因+校内可执行动作”）、底部「生成修改清单」按钮  
- 下一步行动：学生下载Word修改清单 → 在原稿中逐项落实 → 课程截止前重新提交（非本MVP闭环，不设计）  

七、功能取舍  
- 本阶段必须做：  
  ✓ 文档上传与基础校验  
  ✓ 12角色AI并行评审（prompt固化）  
  ✓ 主审AI归因整合与动作映射  
  ✓ PDF报告生成（含锚点）  
  ✓ 修改清单Word一键导出  
- 可以延后：  
  ✗ 教师后台（归档/统计/导出班级报告）  
  ✗ 学生历史报告库  
  ✗ 多轮迭代评审（“修改后重审”）  
  ✗ AI委员语音播报/虚拟形象  
- 明确不做：  
  ✗ AI社区（项目方提及但无任何用户证据指向学生需要“与其他学生AI评审互动”）  
  ✗ AI商城（与评审任务零关联）  
  ✗ AI课程/招聘/社交/游戏（全部为需求假设，无证据表明学生在评审场景中需要这些）  
  ✗ “12个AI委员”对外宣传为“真人导师数字分身”（违反铁律8：AI是手段，虚假拟真损害信任；教师明确反对“让学生误以为在和真人对话”）  

八、关键产品风险  
- 需求风险：学生实际更想要“快速过审”而非“深度反馈”（如为凑学分交差）。但证据显示：课程结项需提交“修改说明”，证明反馈驱动了迭代（简报P6），故“可行动性”是刚需。  
- 使用风险：学生上传扫描件PDF导致OCR失败率高 → 已设人工兜底文案，且首屏强提示“请上传可复制文字的PDF”。  
- 交互风险：报告中“P4用户描述模糊”类归因，学生无法理解“模糊”指什么 → 主审AI强制要求每条归因必须附原文截取（如“原文：‘我们的用户是年轻人’ → 问题：未定义年龄/地域/行为特征”）。  
- 落地风险：大模型API在长文档解析时出现token截断 → MVP限定10页上限，并在上传页明确提示；超限自动拒绝，不进入评审流。  

九、待验证产品假设  
1. 学生愿为获得结构化反馈，接受“上传文档→等待3分钟→下载PDF”这一完整流程（而非继续用微信群问老师）。→ 验证：首校试点中监测上传率与报告打开率。  
2. 教师认可AI报告可替代至少30%的初筛工作量（从而释放精力做深度辅导）。→ 验证：向2位已表示兴趣的教师提供MVP报告样本，请其对照真实学生作业打分“此报告能否支撑我跳过初读环节”。  
3. “校内可执行动作”库（如预约模拟路演）真实存在且可被学生一键触达。→ 验证：与2校创业学院确认3条动作的落地接口（如预约链接、案例库路径、导师排班表）。  

十、产品验证建议  
- 验证对象：首批2所合作高校的各1个双创课程班级（约60名学生+2位教师）  
- 验证方式：**人工MVP**（非代码上线）：教师收集学生作业PDF → 产品官用本地prompt链手动跑12委员+主审流程 → 2小时内邮件返回PDF报告 → 学生按报告修改 → 教师对比修改前后稿评估有效性  
- 核心指标：  
  • 学生报告打开率 ≥85%  
  • 报告中≥2条建议被实际写入修改稿（通过比对终稿与报告建议项）  
  • 教师反馈：“此报告让我节省了至少20分钟/份的初筛时间”比例 ≥70%  
- 通过条件：三项指标全部达成 → MVP成立；任一未达标 → 进入“MVP部分成立，待补证”  

十一、产品设计结论  
**MVP成立**  
理由：主任务清晰（学生3分钟获可行动评审反馈），最短闭环完整（上传→处理→PDF报告→修改清单），功能取舍严格服务于该任务，关键断点（OCR、动作校内适配）均有低成本兜底，且全部设计依据来自已验证的校方调研证据。无需堆砌“AI委员数量”“多模态”“社区”等无关能力——12个AI是评审机制设计，不是功能卖点；真正的MVP价值藏在“P4原文引用→建议补校园地推草图”这句归因里。
