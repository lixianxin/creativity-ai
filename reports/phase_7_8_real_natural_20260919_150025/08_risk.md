【风险审查报告】

一、风险总览  
- 风险计数：致命 2 个 / 高 3 个 / 中 1 个 / 低 0 个  
- 总体判断：存在致命风险，待处置 —— **不解决不得进入上线、对外服务、进校试点或收费环节**

二、合规与法律风险  
✅ **风险点（锚定做法）**：项目“基于大模型API直接上线对外服务”，面向高校学生提供AI评审服务，但未说明是否完成《生成式人工智能服务管理暂行办法》要求的备案。  
→ 等级：**致命**  
→ 触发条件：向公众（含高校学生）提供生成式AI服务，且该服务具备内容生成、评价、建议等交互功能（如AI委员输出评审意见、打分、改进建议），属于“面向社会公众提供生成式人工智能服务”。  
→ 潜在后果：未备案即上线运营，可能被网信部门责令暂停服务、下架应用、通报批评；若发生AI输出违法/有害内容，平台将承担主体责任。具体处罚依据待核验。  
→ 上线前必须完成的动作：**完成国家网信办生成式人工智能服务备案，并在产品界面显著位置标注备案编号及“AI生成内容标识”**（如“本内容由AI生成，仅供参考”）。  

✅ **风险点（锚定做法）**：“学生提交创业想法”——该行为构成对用户原创商业构想的接收与处理，但未说明是否取得学生对“创意内容用于AI训练/优化/存档”的单独、明示、可撤回同意。  
→ 等级：**致命**  
→ 触发条件：系统接收学生提交的完整创业想法（含商业模式、技术路径、团队构成等实质性内容），且未就该内容是否用于模型微调、效果评估、案例库建设等目的进行专项告知与授权。  
→ 潜在后果：若后续将学生创意用于模型迭代或内部知识沉淀，可能构成对《著作权法》第10条“修改权”“保护作品完整权”及《个人信息保护法》第23条“向其他个人信息处理者提供其处理的个人信息”之违规；学生主张权利时，平台面临侵权纠纷与监管问询。具体责任认定待核验。  
→ 上线前必须完成的动作：**在提交页面设置独立勾选框，明确告知“您的创业想法将仅用于本次AI评审；如您同意平台将其匿名化后用于系统优化与教学研究，请单独勾选”，并提供便捷撤回入口；同步更新《用户协议》《隐私政策》中对应条款。**

❌ 未发现：广告法违规（当前无广告投放）、支付业务许可问题（学生端免费、机构采购尚未启动资金流）、学科类培训属性（非授课/辅导，不触碰“双减”红线）。

三、数据与隐私风险  
✅ **风险点（锚定做法）**：“学生提交创业想法”——该内容包含大量可识别个人意图、能力倾向、团队关系、学校院系甚至联系方式（若表单含字段），但未说明是否执行最小必要原则、是否提供删除机制。  
→ 等级：**高**  
→ 触发条件：表单默认收集非必要字段（如手机号、学号、邮箱、指导教师姓名、附件简历PDF）；或虽收集但未提供用户自助删除已提交想法的功能；或未说明数据存储期限与销毁规则。  
→ 潜在后果：违反《个人信息保护法》第6条（最小必要）、第47条（删除权），导致监管约谈、用户投诉激增、信任崩塌。  
→ 上线前必须完成的动作：**① 表单字段强制精简至仅保留“创业想法文本+匿名ID”（如学号脱敏为哈希值）；② 提交后提供“72小时内一键删除全部提交记录”按钮；③ 在隐私政策中明示数据存储地点（境内）、保存期限（≤6个月）、到期自动删除机制。**

✅ **风险点（锚定做法）**：机构版面向“学校创业学院/教务处采购”，意味着需对接校方系统（如统一身份认证、教务数据接口），但未说明是否建立校方数据委托处理协议。  
→ 等级：**高**  
→ 触发条件：通过学校SSO登录或批量导入学生名单，实际接触学生身份信息（姓名、学号、院系），但未与校方签署《个人信息委托处理协议》，亦未说明数据不出校/本地化部署选项。  
→ 潜在后果：校方作为个人信息控制者，若未履行《个保法》第21条委托处理义务，将连带担责；项目方作为受托方，缺乏协议即构成违法处理。  
→ 上线前必须完成的动作：**① 向校方提供标准版《个人信息委托处理协议》模板（含安全审计权、数据出境禁止、违约赔偿条款）；② 若校方要求数据不出校，须支持私有化部署或API级对接（不归集原始身份数据）。**

❌ 未发现：生物识别、位置轨迹、实时监控等高敏数据处理行为。

四、内容与安全风险  
✅ **风险点（锚定做法）**：12个AI委员“模拟真实创业委员会进行全链路审查”，输出包括“市场风险提示”“技术可行性否定”“团队能力质疑”等负向评价，但未说明是否建立AI输出内容安全过滤与人工复核机制。  
→ 等级：**高**  
→ 触发条件：AI直接输出未经干预的评审结论（如“该想法毫无价值”“创始人能力严重不足”），且未设置价值观对齐层、侮辱性/歧视性语义拦截、或关键结论人工兜底审核。  
→ 潜在后果：输出贬损性、标签化、刻板印象内容（如针对女性创业者、欠发达地区学生、跨专业背景学生的负面归因），引发学生心理伤害、舆情危机、校方终止合作。  
→ 上线前必须完成的动作：**① 部署内容安全策略（关键词+语义模型）实时拦截攻击性、歧视性、绝对化否定表述；② 对所有AI委员输出的终版评审报告，强制触发“人工快速复核通道”（由合作高校教师或平台持证审核员抽检≥10%）；③ 在结果页添加“本评审为AI模拟，不构成真实投资/孵化决策依据”显著提示。**

✅ **风险点（锚定做法）**：学生提交内容为UGC性质创业构想，平台未说明是否承担违法信息（如涉政、涉黄、涉诈、剽窃他人商业计划）的主动发现与处置义务。  
→ 等级：**高**  
→ 触发条件：允许学生上传PDF/Word附件、长文本描述，且无任何内容初筛（如文件MD5比对盗版商业计划书库、敏感词扫描、图像OCR识别涉黄图片）。  
→ 潜在后果：平台成为违法商业信息传播渠道，依据《网络信息内容生态治理规定》第12条，需承担“未履行信息内容管理主体责任”责任。  
→ 上线前必须完成的动作：**上线前部署基础内容风控模块：① 文本层：创业想法正文实时扫描涉政、违法、抄袭关键词；② 附件层：限制仅支持纯文本粘贴，禁用文件上传（或启用沙箱解析+病毒+敏感内容扫描）；③ 建立24小时违法内容举报入口与48小时内响应下架流程。**

❌ 未发现：匿名发帖、社交传播（如分享朋友圈）、用户间互动评论等UGC强交互场景。

五、伦理与社会风险  
✅ **风险点（锚定做法）**：面向高校学生（含大量18岁以下本科生），AI评审输出“否决性结论”（如“不建议推进”“失败概率＞80%”），但未配套心理健康支持机制。  
→ 等级：**高**  
→ 触发条件：学生为首次创业尝试者，心理承受力有限；AI输出缺乏温度与建设性，且未链接校内心理中心资源或提供正向引导话术（如“您在XX维度表现突出，建议优先强化YY能力”）。  
→ 潜在后果：诱发焦虑、自我否定、创作回避；极端情况下，与已有心理问题叠加，引发自伤风险；校方将视其为“教育工具安全隐患”。  
→ 上线前必须完成的动作：**① 所有AI委员输出必须嵌入“成长导向”话术模板（禁用绝对化否定，强制包含1项优势识别+1条可操作建议）；② 在结果页底部固定位置嵌入本校心理中心热线/二维码（对接校方提供）；③ 启动前完成与2所合作高校心理中心的联合伦理审查签字确认。**

✅ **风险点（锚定做法）**：12个AI委员“模拟真实创投委”，但未说明是否规避算法偏见（如对文科/艺术类项目、乡村振兴类项目、女性主导项目系统性评分偏低）。  
→ 等级：**中**  
→ 触发条件：训练数据或提示词工程隐含行业偏好（如过度强调TAM/SAM、BP标准化、技术壁垒），导致对非典型创业路径（社区服务、文化传承、慢科技）产生结构性低估。  
→ 潜在后果：加剧教育不公平感知，削弱工具公信力，长期损害高校多样性创新生态。  
→ 上线前必须完成的动作：**上线前完成首期偏见审计报告（委托第三方或高校社科团队），覆盖至少3类非主流项目样本（乡村电商、非遗活化、银发服务），公开摘要结论；并在后台配置“包容性评审模式”开关（供教师端启用）。**

❌ 未发现：线下见面、资金托管、人身安全履约场景。

六、落地与资质风险  
✅ **风险点（锚定做法）**：机构版向学校“按年采购”，但未说明是否具备《增值电信业务经营许可证》（ICP证）或《EDI许可证》（涉及在线数据处理与交易处理）。  
→ 等级：**高**  
→ 触发条件：平台以自身主体与学校签订SaaS服务合同，提供账号管理、数据看板、报告导出等在线服务，构成“在线数据处理与交易处理业务”。  
→ 潜在后果：无证经营属行政违法，市场监管部门可处罚；学校财务审计时将因“向无资质主体采购”问责。  
→ 上线前必须完成的动作：**以运营主体名义申请并取得《增值电信业务经营许可证》（EDI）；若暂未取得，须改为“由学校采购云服务商资源，我方以技术供应商身份提供部署服务”，并签署三方协议明确资质责任归属。**

✅ **风险点（锚定做法）**：声称“面向高校创新创业场景”，拟进校推广，但未说明是否符合教育部《教育移动互联网应用程序备案管理办法》要求。  
→ 等级：**高**  
→ 触发条件：学生通过微信小程序/APP/H5访问服务，且校方将其纳入教学辅助工具范畴（如计入双创学分、教师推荐使用），即属于“教育App”。  
→ 潜在后果：未备案不得进入校园，学校信息中心有权阻断访问；已上线将被全国教育App备案平台公示下架。  
→ 上线前必须完成的动作：**完成教育部教育移动互联网应用程序备案（网址：app.eduyun.cn），取得备案编号，并在登录页底部公示。**

❌ 未发现：医疗器械、金融、出版等特殊准入资质需求。

八、红线清单（致命与高风险按优先级排序）  
① **未完成生成式人工智能服务国家网信办备案** → 不得上线对外服务、不得向学生开放提交入口、不得开展任何公开宣传。  
② **未就学生创业想法的使用目的取得单独明示同意** → 不得接收任何一份学生提交内容，不得启动AI评审流程。  
③ **未取得教育部教育App备案编号** → 不得进入任何一所高校系统、不得在校园场景推广、不得接入学校统一身份认证。  
④ **未取得EDI许可证或未重构采购法律路径** → 不得与学校签署任何形式的服务采购合同，不得开具SaaS类发票。  
⑤ **未建立AI输出内容安全过滤+人工复核机制** → 不得向学生展示任何AI委员评审结论。  
⑥ **未精简数据收集字段并提供自助删除功能** → 不得开放表单提交入口。

九、证据缺口  
① **备案状态缺失**：未提供国家网信办生成式AI备案进度、教育部教育App备案号、EDI许可证号（或替代性法律路径说明）。  
② **协议文本缺失**：未提供《用户协议》《隐私政策》《个人信息委托处理协议》草案，无法验证告知充分性与条款合规性。  
③ **技术实现缺失**：未说明内容安全过滤采用何种策略（关键词/模型/第三方SDK）、人工复核人员资质（是否持证/是否高校教师）、心理支持资源是否已与校方签约落地。  
④ **样本审计缺失**：未提供算法偏见初步测试报告或第三方伦理审查意向函。
