【产品设计报告】

一、核心用户任务  
- 用户是谁/角色：高校创新创业课程学生（主任务执行者）、创业学院指导教师（关键影响者与MVP协同验证者）  
- 要完成的任务：在提交创业想法后，**快速获得结构化、可行动的评审反馈**，用于迭代方案、准备路演或课程作业交付  
- 当前痛点：  
  • 学生提交BP/创意后，平均等待人工评审超5–7个工作日（用户洞察官报告引用：2校调研中83%学生称“反馈滞后导致错过课程节点”）；  
  • 现有反馈多为模糊评价（如“想法不错”“需加强市场分析”），缺乏分维度打分、归因依据和改进建议；  
  • 教师人力有限，无法对每份方案做≥3轮深度批注，常以“建议参考模板”替代个性化指导。  
- 任务目标（一句话）：**学生在提交创业想法后10分钟内，获得一份由12个AI委员模拟的真实评审报告，包含维度评分、关键质疑、归因依据及3条可立即执行的修改建议，支撑其当堂课/当天完成方案迭代。**  
- 证据状态：**有据**（来自用户洞察官报告：2校教师访谈+32份学生作业回溯日志；明确记录“等待反馈”与“反馈不可用”为TOP2断点）

二、核心使用场景  
- 触发场景：学生在创新创业课结课前48小时、校级创业训练计划申报截止前72小时、或日常课程作业提交后，点击“申请AI评审”  
- 输入：一份文本型创业想法（支持粘贴/上传Word/PDF，≤2000字；字段明确：项目名称、解决什么问题、目标用户、如何赚钱、当前进展）  
- 处理过程：系统将输入分发至12个角色化AI委员（如“技术可行性委员”“早期用户获取委员”“财务可持续性委员”），各自独立生成带推理链的评审意见，再聚合生成共识结论与分歧提示  
- 用户期望结果：不是“AI说了什么”，而是“我下一步该改哪三处？为什么？改完就能过初筛吗？”

三、核心产品路径  
1. **学生粘贴/上传创业想法文本 → 系统自动提取5个结构化字段（若缺失则提示补全，不强制）**  
2. **点击“启动AI评审” → 后台调用12路大模型API（角色指令+评审框架约束），并行生成带依据的评审意见（含评分、质疑点、原文引用、改进建议）**  
3. **系统聚合生成1份主报告（含：①总分+各维度雷达图；②3条最高优先级修改建议；③2个最可能被真实评委挑战的问题+应答话术草稿）**  
4. **学生阅读报告 → 点击“生成修改版BP”（仅重写被标记段落，保留原风格）→ 下载/复制 → 完成迭代闭环**  

▶ 关键断点：  
- 步骤1：学生不愿重写结构化字段 → 断点在“输入成本过高”；兜底：纯文本粘贴+AI自动解析（MVP阶段接受70%字段识别率，人工兜底由教师后台补录）  
- 步骤2：12路并发导致延迟或幻觉 → 断点在“输出不可信”；兜底：首版只启用3个高权重委员（市场/可行性/商业模式），其余角色暂作“评审观察员”仅输出关键词，不参与打分与建议生成  
- 步骤4：“生成修改版BP”若质量差，学生直接弃用 → 断点在“输出不可执行”；兜底：该功能设为“一键展开”非默认动作，主报告末尾提供“手动修改指引”（如：“请重写‘目标用户’段：需补充年龄/地域/行为特征，示例→…”）

四、MVP最小闭环  
- 必须有：  
  ✓ 文本输入（粘贴框+基础格式清洗）  
  ✓ 3个角色AI委员（市场验证委员、技术可行性委员、商业模式委员）独立评审+带原文引用的质疑  
  ✓ 主报告页：总分+3维雷达图+3条可执行修改建议+2个高频挑战问题+应答话术草稿  
  ✓ “一键展开”式修改指引（非生成全文，而是定位段落+给改写公式）  
- 暂不需要：  
  ✗ 12个委员全部上线（其余9个角色仅存档指令集，不调用）  
  ✗ PDF/Word解析（MVP仅支持纯文本粘贴；教师端可人工补字段）  
  ✗ 学生账号体系（用微信扫码临时会话，不存历史记录）  
  ✗ 教师管理后台（首期用飞书表格人工汇总反馈）  
- 人工兜底：  
  • 教师可登录共享链接查看学生报告，并在飞书文档中手写1条“真人加批注”（标注“AI未覆盖但重要的一点”）  
  • 所有AI输出底部固定提示：“本报告由AI模拟生成，最终评审以创业学院线下会议为准”

五、核心功能  
| 功能 | 服务的用户任务 | 优先级 | 依据 | 验证状态 |  
|------|----------------|--------|------|-----------|  
| 文本输入框（支持粘贴+自动字段识别） | 降低提交门槛，触发评审任务 | 核心 | 任务起点，无此则闭环不存在 | 有据（学生拒绝填写表单是已验证断点） |  
| 3角色AI委员并行评审（带原文引用+质疑归因） | 提供可信、可追溯的反馈依据 | 核心 | 解决“反馈不可用”痛点，替代模糊评价 | 有据（教师强调“要看到质疑从哪来”） |  
| 主报告页：3维雷达图+3条修改建议+2个挑战问题 | 让学生10分钟内知道“改什么、为什么、怎么答” | 核心 | 直接对应任务目标中的“可立即执行” | 有据（学生作业日志显示“最需要的是具体修改项”） |  
| “一键展开”修改指引（定位段落+给公式） | 将反馈转化为当堂可操作动作 | 支撑 | 让“知道改什么”变成“立刻能动手”，路径更短 | 有据（教师反馈“学生最缺的是改写脚手架”） |  
| 微信扫码临时会话 | 避免注册流失，适配课程场景碎片化使用 | 支撑 | 降低第一步阻力，人工兜底可行 | 有据（2校均用企业微信授课，扫码即达） |  
| PDF/Word解析 | 提升输入体验 | 延后 | MVP阶段文本粘贴已覆盖92%作业格式（用户洞察官数据） | 有据，但非主任务必需 |  
| 12委员全量运行 | 增强“委员会感” | 延后 | 无证据表明委员数量>3提升反馈质量；反增延迟风险 | 需求假设待验证 |  
| 学生历史报告库 | 满足长期成长追踪 | 不做 | 主任务是“单次快速迭代”，非“成长档案”；增加复杂度且无需求证据 | 明确不做（不服务于主任务） |  

六、关键交互设计  
- 用户输入：粘贴一段≤2000字的创业想法文本（系统实时提示“已识别：项目名✓，问题✓，用户✓，模式✓，进展⚠️未提及”）  
- 系统处理：调用3路大模型API（角色指令含：①必须引用原文句子；②每个质疑需对应1个课程评分标准条款；③建议必须可单步执行）  
- 用户确认：无——评审为单向触发，不需学生确认中间步骤（避免增加路径长度）  
- 输出结果：一页A4宽度主报告（PDF可下载+网页可读），含：总分（0–100）、3维雷达图（市场/技术/模式）、3条加粗建议（如：“重写目标用户段：需补充‘18–25岁在校大学生，月均外卖频次≥12次，曾因取餐难放弃订单’”）、2个挑战问题（如：“如果校园只允许1家配送商入驻，你的壁垒是什么？”）+应答话术（“我们已与3个宿舍楼自组织团队签约独家取餐代理，合同模板见附件”）  
- 下一步行动：点击“展开修改指引” → 页面高亮原文对应段落 → 右侧显示改写公式+示例 → 复制后粘贴回原稿  

七、功能取舍  
- 本阶段必须做：  
  ✓ 纯文本输入+字段识别提示  
  ✓ 3角色AI委员评审（带原文引用、评分、建议）  
  ✓ 主报告页（雷达图+3建议+2挑战+话术）  
  ✓ 微信扫码临时会话  
  ✓ “一键展开”修改指引（非生成，是教学脚手架）  
- 可以延后：  
  ▷ PDF/Word解析（文本粘贴已覆盖主场景）  
  ▷ 委员角色扩展至6个（先验证3个是否解决核心痛点）  
  ▷ 教师后台数据看板（飞书表格人工汇总足够MVP验证）  
- 明确不做：  
  ✗ AI绘图/视频/商城/课程/招聘/社交/游戏 —— 项目材料未提及相关用户任务，属功能堆砌，无任何证据支撑  
  ✗ 学生账号体系与历史报告存储 —— 违反“单次快速迭代”主任务，增加冷启动与隐私负担  
  ✗ 实时多人协作编辑BP —— 属于“团队创作工具”，非“评审反馈工具”，任务错位  
  ✗ 对接教务系统学籍数据 —— 无需求证据，且引入合规风险，主任务无需身份强绑定  

八、关键产品风险  
- 需求风险：学生把AI报告当“终审结论”，忽略教师终裁权 → 兜底：所有报告底部强提示+教师可追加1条人工批注  
- 使用风险：AI质疑过于尖锐打击学生信心（如“此想法零创新”） → 兜底：指令中强制加入建设性框架（“指出缺口→给出填补路径→示例”三段式输出）  
- 交互风险：雷达图维度引发学生质疑“为什么没评团队？” → 兜底：仅展示3个课程评分标准明文规定的维度（已由2校教师联合确认）  
- 落地风险：大模型API响应超时或乱码 → 兜底：前端设置15秒超时，自动降级为“3位委员意见摘要+人工审核入口”（教师飞书通知）  

九、待验证产品假设  
1. 学生愿为“10分钟反馈”放弃等待教师人工评审（假设：速度价值 > 权威性折损）→ 需验证是否真缩短迭代周期  
2. 3个维度评审足以覆盖80%课程作业评分焦点（假设：市场/技术/模式是教师实际打分权重TOP3）→ 需验证教师真实评分维度分布  
3. “修改指引”比“全文重写”更能驱动学生动手（假设：脚手架式引导比全自动替代更促进行为改变）→ 需验证学生实际修改率与版本采纳率  

十、产品验证建议  
- 验证对象：2所合作高校的2个创新创业课班级（共约120名学生）  
- 验证方式：**人工MVP（Wizard of Oz）** —— 前3天：教师用飞书文档人工模拟3委员评审（按统一模板填写），系统仅做页面渲染与报告组装；后7天：接入真实大模型API，但教师后台可一键替换任意AI意见为人工修订版  
- 核心指标：  
  • 学生从提交到首次打开报告的平均时长（目标≤8分钟）  
  • 报告中“3条建议”被学生实际修改的条目数（目标≥2.1条/人）  
  • 教师在飞书文档中追加人工批注的比例（目标≥40%，证明AI未覆盖关键盲区）  
- 通过条件：7日内，≥65%学生完成至少1次“提交→读报告→修改”闭环，且教师反馈“AI报告节省了≥50%初筛时间”

十一、产品设计结论  
**MVP成立**  
主任务清晰（学生需10分钟内获可执行评审反馈），最短闭环完整（粘贴→评审→报告→修改指引），功能取舍严格锚定单一任务，关键断点均有低成本兜底（人工补字段、人工追加批注、指令约束AI语气），且全部设计基于已验证用户证据。无需扩展功能广度，首期唯一目标：验证“AI能否成为创业教育中可信赖的即时反馈脚手架”。
