【风险审查报告】

一、风险总览  
- 风险计数：致命 2 个 / 高 3 个 / 中 1 个 / 低 0 个  
- 总体判断：存在致命风险，待处置 —— **不解决不得进入上线、对外服务、进校试点或收费环节**

---

二、合规与法律风险  
✅ **风险点（锚定做法）**：项目基于大模型API直接上线对外服务，面向高校学生提供AI生成式评审意见（含商业逻辑、技术可行性、市场分析等结构化判断），但未说明是否完成《生成式人工智能服务管理暂行办法》要求的备案。  
→ 等级：**致命**  
→ 触发条件：向公众（含高校学生）提供生成式AI服务，且该服务输出具有决策参考性质的结构化评审结论（非单纯文本润色或问答）。  
→ 潜在后果：未备案即上线属行政违法，可能被网信部门责令暂停服务、下架应用、通报教育主管部门；若评审结论引发学生重大决策失误（如放弃真实创业机会、误判技术路径），平台可能被追究算法服务提供者责任。具体罚则待核验。  
→ 上线前必须完成的动作：**完成国家网信办生成式人工智能服务备案，并在产品界面显著位置公示备案编号与《AI生成内容标识规范》执行说明**。

✅ **风险点（锚定做法）**：机构版向学校创业学院/教务处按年采购，但未说明资金是否经由平台归集、结算路径是否涉及“代收代付”。若学校付款至平台账户，平台再向第三方大模型服务商（如阿里云、百度智能云）支付API调用费，则构成资金经手。  
→ 等级：**致命**  
→ 触发条件：平台作为非持牌机构，收取学校对公款项后向AI服务商支付费用，形成“学校→平台→大模型厂商”的资金流闭环。  
→ 潜在后果：涉嫌无证从事支付结算业务（“二清”），违反《非银行支付机构监督管理条例》及央行关于资金清算的监管要求，可能触发金融监管部门联合执法，导致账户冻结、业务关停。具体认定标准与处罚幅度待核验。  
→ 上线前必须完成的动作：**切换为“学校直付模式”——由学校与大模型服务商签署API采购协议并直接支付；平台仅提供SaaS技术服务，收取纯软件服务费（不开具“信息服务+支付结算”混合发票），且所有合同、发票、资金流均隔离于API费用之外**。

❌ 未发现其他合规与法律风险（如广告法、反不正当竞争、双减——本项目不提供学科类培训或K12辅导）。

三、数据与隐私风险  
✅ **风险点（锚定做法）**：学生提交“创业想法”，内容必然包含个人信息（姓名、学号、院系、联系方式）、商业构想（可能含技术方案、原型图、供应链信息）、甚至个人身份特征（如“聋人团队开发无障碍APP”）。项目未说明数据收集范围、最小必要性设计、告知同意机制、存储位置与删除路径。  
→ 等级：**高**  
→ 触发条件：未经单独、明示、可撤回的授权，收集学生姓名+学号+院系+手机号等组合信息；或未提供“一键删除全部提交记录与AI评审历史”的自助功能。  
→ 潜在后果：违反《个人信息保护法》第6条（目的限定）、第17条（告知义务）、第47条（删除权），可能引发学生投诉、教育主管部门约谈、省级网信办专项检查。  
→ 上线前必须完成的动作：**上线前发布独立《学生端隐私政策》，明确列出每项收集字段的用途、法律依据、存储期限（建议≤6个月）、境外传输情况（如大模型API调用涉及境外服务器需单独说明并获单独同意）；在提交页嵌入勾选式授权弹窗（非默认勾选）；提供学生后台“永久删除本人全部数据”按钮，且72小时内完成物理删除（含备份）**。

✅ **风险点（锚定做法）**：高校机构版采购后，学校可能要求数据本地化（如评审记录存于校内服务器），但项目当前架构基于大模型API直连，未说明是否支持私有化部署或API结果脱敏回传。  
→ 等级：**高**  
→ 触发条件：学校提出数据不出校要求，而平台无法提供接口级数据隔离方案（如仅回传评审结论摘要，原始创意文本不上传云端）。  
→ 潜在后果：导致机构采购失败；若强行签约后无法履约，构成合同违约；在教育系统数据安全专项整治中被列为高风险供应商。  
→ 上线前必须完成的动作：**明确披露当前服务的数据流向图（含大模型服务商名称、服务器所在地、是否加密传输），并书面承诺：机构版可选“轻量私有化模式”——学生创意文本在校内终端本地解析为结构化特征向量，仅上传向量至云端AI委员进行评审，原始文本永不离校**。

❌ 未发现生物识别、位置轨迹、设备指纹等过度收集行为（项目描述未涉及）。

四、内容与安全风险  
✅ **风险点（锚定做法）**：12个AI委员模拟真实评审，输出含“否决建议”“风险警示”“竞品碾压”等强判断性结论，但未说明是否对AI输出设置内容安全过滤、事实核查机制或人工复核兜底。  
→ 等级：**高**  
→ 触发条件：AI生成评审意见中出现明显事实错误（如“该技术已被华为2023年专利覆盖”实为捏造）、歧视性表述（如“女性主导团队融资成功率低”）、或诱导性结论（如“建议立即注册公司，否则丧失先机”）。  
→ 潜在后果：误导学生重大决策；若被截图传播，损害平台公信力；在教育场景中引发舆情危机（如“AI把学生梦想判了死刑”）；违反《生成式人工智能服务管理暂行办法》第4条（尊重社会价值观）、第12条（避免歧视与误导）。  
→ 上线前必须完成的动作：**部署三层内容安全机制：① 输入层关键词拦截（屏蔽政治/宗教/暴力等禁词）；② 输出层LLM Guard规则引擎+事实一致性检测（对接公开专利库、工商数据库做基础校验）；③ 对TOP10%高风险结论（如“技术不可行”“市场已饱和”）强制触发人工审核通道（由合作高校教师志愿者池响应，平均响应<2小时）**。

✅ **风险点（锚定做法）**：学生提交内容含UGC属性（创业想法本质是用户原创表达），平台未说明是否承担违法信息连带责任。若学生故意提交涉政、涉黄、涉诈创业点子（如“开发翻墙路由器”“代理境外赌博引流”），AI委员是否识别并阻断？  
→ 等级：**高**  
→ 触发条件：平台未建立UGC内容初审机制，允许任何创业想法直达AI评审流程。  
→ 潜在后果：成为违法信息传播渠道，触发《网络信息内容生态治理规定》第21条平台主体责任，面临网信部门约谈、限期整改。  
→ 上线前必须完成的动作：**在提交入口设置“创业想法合规承诺书”强制阅读+勾选；部署前置AI初筛模型，对提交文本进行违法/违规/违背公序良俗关键词+语义识别，命中即拦截并提示“该方向不符合国家创新创业导向”，禁止进入评审流程**。

❌ 未发现匿名发帖、社交传播、朋友圈分享等UGC分发机制（项目描述未提及），故无网暴、诽谤、隐私泄露链式风险。

五、伦理与社会风险  
✅ **风险点（锚定做法）**：面向高校学生（含大量18岁以下本科生），AI委员输出“全链路审查”结论，可能强化算法权威感，使学生过度依赖AI判断，削弱批判性思维与试错勇气。  
→ 等级：**中**  
→ 触发条件：评审报告未标注“AI模拟结论，非真实投资决策依据”，且未嵌入成长性引导话术（如“此结论基于当前公开信息，建议你访谈10位潜在用户验证”）。  
→ 潜在后果：长期使用可能导致学生决策能力退化；在教育伦理审查中被质疑“用AI替代育人过程”。  
→ 上线前必须完成的动作：**所有AI评审报告首屏强制显示浮动提示条：“本结论由AI模拟生成，仅供参考。真实创业需实地验证、持续迭代。我们鼓励你带着这份报告去找创业导师聊聊。”——该提示不可关闭、不可折叠**。

❌ 未发现算法歧视训练数据偏见（项目未披露训练方式）、未发现弱势群体排斥（如未限制残障学生使用）、未发现心理健康危机干预场景（无自伤/抑郁相关内容输入）。

六、落地与资质风险  
✅ **风险点（锚定做法）**：项目定位为“面向高校创新创业场景”，拟推进“进校”，但未说明是否具备《教育移动互联网应用程序备案管理办法》要求的教育App备案。  
→ 等级：**高**  
→ 触发条件：以“高校创业评审工具”名义接入学校统一身份认证（如CAS）、嵌入教务系统、或通过学校官方渠道推广（如创业学院公众号导流）。  
→ 潜在后果：未备案教育App不得进入校园信息化系统，学校信息中心有权拒绝对接；教育部开展教育App专项治理时将被下架。  
→ 上线前必须完成的动作：**取得教育部教育移动互联网应用程序备案编号，并在应用商店详情页、官网底部、登录页显著位置展示备案号及查询链接**。

✅ **风险点（锚定做法）**：声称“12个AI委员模拟真实创业委员会”，但未说明是否获得真实创投机构、产业专家授权使用其方法论、术语体系或评审框架。若直接复刻某知名VC的“七步尽调法”并冠以其名，可能侵犯知识产权或构成不正当竞争。  
→ 等级：**高**  
→ 触发条件：AI委员命名或评审维度中出现真实机构名称（如“红杉版AI委员”“真格打分模型”），或评审报告引用未授权的 proprietary framework。  
→ 潜在后果：遭知识产权诉讼；被行业组织联合抵制；损害高校合作信任。  
→ 上线前必须完成的动作：**所有AI委员采用中性命名（如“市场洞察委员”“技术可行性委员”），评审维度基于公开学术文献（如《创业研究》期刊通用评估模型）构建，禁用任何商业机构专属方法论名称；在帮助文档中注明“本系统评审逻辑参考《创业管理：理论与实践》（第4版）等公开教材”**。

❌ 未发现线下履约（无见面、无交付实物）、未发现特定行业准入许可需求（非医疗/金融/驾驶等强监管领域）。

八、红线清单（致命与高风险按优先级排序）  
① **完成国家网信办生成式人工智能服务备案，并公示备案编号与AI标识规范**（致命｜不完成不得上线对外服务）  
② **终止平台经手学校采购资金，切换为“学校直付大模型服务商+平台纯收SaaS服务费”模式，确保资金流零经手**（致命｜不完成不得签署任何机构合同）  
③ **上线前发布符合《个人信息保护法》要求的学生端隐私政策，实现最小必要收集、明示授权、一键永久删除**（高｜不完成不得开放学生提交功能）  
④ **取得教育部教育移动互联网应用程序备案编号，并在所有触点公示**（高｜不完成不得接入任一学校信息系统或官方推广渠道）  
⑤ **部署UGC内容初筛+AI评审输出安全过滤+高风险结论人工复核三重机制，杜绝违法/误导/歧视内容流出**（高｜不完成不得启动AI评审流程）

九、证据缺口  
① **未提供当前技术架构图**：无法确认大模型API调用是否经过平台服务器中转（影响二清判定）、原始创意文本是否落盘、是否具备私有化部署能力。  
② **未提供AI委员训练/提示工程说明**：无法判断是否存在隐性偏见、是否复用受版权保护的评审框架、是否具备事实核查能力。  
③ **未提供学生端数据收集清单与授权文本草案**：无法验证是否满足“单独同意”“明示目的”等法定要件。  
④ **未说明是否已与高校签订试点协议或保密协议**：若已有校方背书但未完成教育App备案，将放大合规风险。

十、风险审查结论  
**存在致命风险，待处置**  

> 注：当前项目处于概念验证阶段（2所高校老师口头兴趣），尚未上线、未收费、未进校。但所有致命风险均具有“行为即违法”性质——只要开始对外提供AI评审服务、只要签署第一份学校采购合同、只要接收第一个学生创意文本，即触发监管责任。因此，**严禁以“小范围灰度”“内部测试”为由绕过上述红线**。所有动作须在首次学生提交、首次学校签约、首次对外宣传前100%就绪，并留存可审计的合规证据链（备案截图、合同修订页、隐私政策发布快照、安全机制测试报告）。
