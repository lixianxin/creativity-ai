【产品设计报告】

一、核心用户任务  
- 用户是谁/角色：高校创新创业课程学生（主任务执行者）、创业学院指导教师（关键影响者与MVP协同验证者）  
- 要完成的任务：在课程作业/项目申报截止前，**独立完成一份具备基本商业可行性说服力的创业想法初稿，并获得可行动的、具体到修改点的反馈**，而非泛泛而谈的“有潜力”或“需完善”。  
- 当前痛点：  
  - 学生提交BP后，7–14天才能收到教师人工评审（教务处报告引用：“83%学生反馈反馈滞后导致迭代中断”）；  
  - 现有AI工具（如ChatGPT写BP）输出空洞、缺乏评审视角（无风险识别、无资源匹配校验、无高校场景约束意识）；  
  - 教师面临百人级班级，无法对每份想法做结构化打分与归因式批注（竞品报告指出：现有教务系统仅支持“通过/不通过”二值标记）。  
- 任务目标（一句话）：**学生在提交创业想法5分钟内，获得由12个差异化AI委员模拟的真实评审团输出——含一致性结论、分歧点标注、3项最紧急修改建议，且每条建议均可直接用于重写BP段落。**  
- 证据状态：**有据**（来源：项目方提供的2校教师访谈纪要 + 教务处《双创课程过程性评价痛点白皮书》第3.2节）

二、核心使用场景  
- 触发场景：学生在创新创业课结课前72小时，打开课程平台提交「一句话想法+300字描述」（非完整BP），点击「申请AI预评审」  
- 输入：  
  - 必填：一句话创业主张（例：“为大学生提供按小时计费的实验室设备共享平台”）  
  - 选填：1张手绘草图/1个竞品名/1个已接触的校内资源（如“已联系材料学院张老师开放X设备”）  
- 处理过程：12个AI委员（角色预设：技术专家/财务风控/高校政策顾问/学生用户代表/供应链老兵等）基于统一评审框架（含6维校验：需求真实性、技术可行性、资源可及性、政策合规性、商业模式简明性、校园落地优先级）独立生成评审意见，系统聚合共识与冲突  
- 用户期望结果：不是“评分”，而是**可立即执行的改写指令**（例：“将‘共享设备’改为‘预约校内闲置3D打印机’——当前表述未体现校园资源复用特征，易被误判为校外商业平台”）

三、核心产品路径  
1. 学生粘贴/输入一句话想法 + 300字描述 → 点击「提交预评审」  
2. 系统校验输入完整性（≥20字符，含主语+动词+对象）→ 若不满足，弹出引导模板（非强制填写，但提示“92%高分想法含明确服务对象”）  
3. 启动12委员并行评审（后台调用大模型API，每个委员带角色prompt+高校双创知识库片段）→ 聚合生成：  
　　✓ 共识结论（例：“8/12委员确认需求真实，但全部要求补充校内资源验证”）  
　　✓ 分歧热区（例：“技术专家组认为可行，政策顾问组指出需规避《高校实验室安全管理办法》第5条”）  
　　✓ 3条「改写级建议」（每条含原文定位+修改句式+理由，如：“原文‘解决设备短缺’→ 改为‘释放本校工程训练中心闲置CNC机床87小时/周’；理由：高校评审关注存量资源激活，非抽象问题”）  
4. 学生阅读结果 → 点击「一键插入修改建议至我的文档」（自动跳转至内置轻编辑器，光标定位在对应段落，已填充修改句式）→ 完成闭环  

**关键断点**：  
- 断点①：学生输入过短（<50字符）时，AI委员输出易失焦 → **人工兜底：触发时弹出1个真实学生案例对比（“类似想法：‘帮同学修电脑’→ 优化后：‘为XX大学计算机学院本科生提供学分置换的硬件故障快修服务’”）**  
- 断点②：建议不可执行（如仅说“加强市场分析”）→ **MVP硬约束：所有建议必须含「可替换原文片段」+「修改后句式」，否则该委员输出被系统过滤**  
- 断点③：学生不理解“政策顾问组分歧” → **支撑功能：悬停查看《高校实验室安全管理办法》第5条原文摘要（非全文，仅28字关键句）**

四、MVP最小闭环  
- 必须有：  
  ✓ 单文本输入框（一句话+300字）  
  ✓ 12委员角色化评审引擎（每个委员prompt含角色定义+3条高校评审禁忌）  
  ✓ 共识/分歧/改写建议三模块聚合页  
  ✓ 「一键插入」轻编辑器（仅支持段落级覆盖，无格式编辑）  
- 暂不需要：  
  ✗ 多轮迭代记录（学生重提→历史对比）  
  ✗ 教师后台管理面板（如批量导出、打分权重调整）  
  ✗ 学生账号体系（用课程平台OAuth临时token即可）  
  ✗ AI委员形象化UI（头像/发言气泡）  
- 人工兜底：  
  ✓ 评审知识库由创业学院教师提供5条高频否决原因（如“未说明如何规避学生创业保险缺失风险”），MVP阶段以静态规则注入prompt，非实时RAG  
  ✓ 当某委员输出未含「可替换句式」，由运营人工补1条（日限20次，监控触发率＞5%即升级prompt）

五、核心功能  
| 功能 | 服务的用户任务 | 优先级 | 依据 | 验证状态 |  
|------|----------------|--------|------|----------|  
| 单文本输入+校验 | 确保学生交付可评审的最小信息单元 | 核心 | 任务目标要求“5分钟内获得反馈”，输入越轻，启动越快；教务处数据：76%学生放弃使用因表单超5字段 | 有据 |  
| 12委员角色化评审引擎 | 提供多视角、有冲突的真实感反馈，避免AI幻觉式一致 | 核心 | 教师访谈原话：“学生需要看到专家吵架，才知道哪条建议真该听” | 有据 |  
| 改写级建议三件套（定位+句式+理由） | 让学生无需理解评审逻辑，直接完成BP迭代 | 核心 | 任务目标中“可直接用于重写BP段落”为刚性要求；无此功能=闭环断裂 | 有据 |  
| 一键插入轻编辑器 | 消除“看懂建议→打开Word→找到位置→手动修改”动作损耗 | 核心 | 用户洞察官报告：学生平均在反馈后2.3天才开始修改，主因是上下文切换成本 | 有据 |  
| 悬停政策条款摘要 | 降低专业术语理解门槛，支撑建议可信度 | 支撑 | 断点③需兜底；但可人工维护5条，非必须AI抽取 | 有据 |  
| 教师反馈入口（仅文字框） | 收集教师对AI建议质量的即时修正 | 支撑 | MVP需快速迭代委员prompt，教师是唯一校准源；但非学生任务必需 | 有据 |  
| 多轮历史对比 | 支持学生追踪改进轨迹 | 延后 | 任务目标未要求“成长性”，属增强体验；教务处未提出此需求 | 需求假设待验证 |  
| AI委员3D形象动画 | 提升趣味性 | 不做 | 无任何用户证据表明此服务于“获得可行动反馈”任务；增加首屏加载延迟，损害5分钟闭环 | 明确不做 |  

六、关键交互设计  
- 用户输入：纯文本框（无标题/无附件/无格式），底部浮动提示：“参考写法：为[谁]解决[什么问题]，用[什么方式]，已链接[校内什么资源]”  
- 系统处理：输入提交后，显示「12位委员正在审阅您的想法…（预计42秒）」+ 实时进度条（非真实进度，防焦虑；实际API调用约35秒）  
- 用户确认：结果页顶部强提示「这是预评审，非终审结论」+ 底部按钮「我已修改，申请教师终审」（直链教务系统，非本产品功能）  
- 输出结果：三栏卡片式布局——左栏共识（绿色）、中栏分歧（黄色预警图标）、右栏改写建议（蓝色高亮可点击句式）  
- 下一步行动：点击任一建议句式 → 自动跳转轻编辑器，光标定位原文段落，输入框已填充修改后句子，旁注“点击✓应用，或手动编辑”  

七、功能取舍  
- 本阶段必须做：  
  ✓ 单文本输入与智能校验（含引导模板）  
  ✓ 12委员角色化评审引擎（含高校知识库规则注入）  
  ✓ 三模块聚合页（共识/分歧/改写建议）  
  ✓ 一键插入轻编辑器（段落级覆盖）  
- 可以延后：  
  △ 教师后台（仅需MVP期间人工导出CSV）  
  △ 学生数据看板（如“你的想法在全校相似度排名”）  
  △ 多模态输入（上传草图自动OCR解析）  
- 明确不做：  
  ✗ AI委员语音播报（不服务于“获得可行动反馈”，增加延迟与误听风险）  
  ✗ 创业想法数据库（项目方提出“积累10万想法训练专属模型”）→ **砍掉理由：此服务于长期AI能力，不服务于学生“5分钟获得改写建议”主任务；且10万低质想法将污染评审逻辑**  
  ✗ 校友投资人AI分身（项目方提出“接入校友库生成投资人视角”）→ **砍掉理由：无教师/学生证据表明需投资人视角；高校评审核心是“能否进校落地”，非“能否融资”**  
  ✗ 社区讨论区（项目方提出“学生互评”）→ **砍掉理由：扩大任务边界，主任务是“学生获专业反馈”，非“构建评价社区”；且冷启动风险极高**  

八、关键产品风险  
- 需求风险：学生可能将“预评审”误认为终审，跳过教师环节 → **兜底：结果页顶部红字声明+强制勾选“我理解此非终审”才能导出PDF**  
- 使用风险：教师发现AI建议与自身判断严重偏离，质疑系统可靠性 → **兜底：每条建议附“本建议依据《XX高校双创评审指南》第X条”，并设“反馈此建议”按钮直连教师邮箱**  
- 交互风险：轻编辑器插入后格式错乱（如原文含表格）→ **兜底：MVP限定仅支持纯文本段落；检测到复杂格式时提示“请复制纯文本再试”**  
- 落地风险：大模型API响应波动导致超时 → **兜底：前端设45秒硬超时，超时后返回“委员们正在激烈辩论，请稍候重试”，不展示部分结果（宁缺毋滥）**  

九、待验证产品假设  
1. 学生愿为「5分钟获得3条可插入修改建议」付出认知成本（输入一句话+300字），而非直接交空白稿 → **验证：首校试点首日，统计输入完成率 vs 弃用率**  
2. 教师认可“分歧热区”比“平均分”更有教学价值 → **验证：向2位教师提供匿名评审报告，询问“你会用哪类信息给学生面批？”**  
3. “改写级建议”的句式准确率＞85%（即学生直接采用后，教师终审通过率提升） → **验证：收集首批50份学生修改稿，由第三方教师盲评“是否解决原问题”**  

十、产品验证建议  
- 验证对象：2所合作高校的各1个双创课程班级（共约120名学生+4位指导教师）  
- 验证方式：**人工MVP** —— 前3天：教师用真实评审标准手写3条改写建议，系统仅做“格式化呈现+一键插入”；后7天：切换为AI评审，对比两组学生BP修改完成率与教师终审通过率  
- 核心指标：  
  - 学生从提交到完成首次修改的中位时长（目标≤24小时）  
  - 教师对AI建议“可直接用于教学反馈”的满意度（NPS≥40）  
  - AI建议被学生实际采纳率（埋点统计“一键插入”点击率）  
- 通过条件：  
  - 时长指标达标 + 满意度达标 + 采纳率＞65% → MVP成立  
  - 任一指标未达标 → 进入“MVP部分成立，待补证”  

十一、产品设计结论  
**MVP成立**  

（依据：主任务清晰锚定“学生5分钟获可行动改写建议”；最短闭环仅4步，无冗余环节；所有核心功能均刚性服务于该任务；关键断点均有低成本人工兜底；项目方堆砌的“AI社区/商城/招聘”等功能已被明确剔除，未污染MVP边界）
