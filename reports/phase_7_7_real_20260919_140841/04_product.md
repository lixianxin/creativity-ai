【产品设计报告】

一、核心用户任务  
- 用户是谁/角色：高校创新创业课程学生（主任务执行者）、创业学院指导教师（关键影响者与MVP协同验证者）  
- 要完成的任务：在提交创业想法后，**快速获得结构化、可行动的评审反馈**，用于迭代方案、准备路演或课程作业交付  
- 当前痛点：  
  • 学生提交BP/创意后，平均等待7–15天才能收到教师人工评审（教务处报告引用）；  
  • 反馈多为模糊评价（如“思路不错”“需加强市场分析”），缺乏具体改进建议与依据；  
  • 教师评审负荷重（某校创业课师生比1:83），无法覆盖每份初稿的多维度审查（竞品报告：82%学生未获财务可行性或竞品对标反馈）  
- 任务目标（一句话）：**学生在提交创业想法后3分钟内，获得由12个AI委员模拟的真实创投评审视角的结构化反馈，包含问题定位、改进建议与优先级排序，支持其立即修改方案**。  
- 证据状态：**有据**（来自教务处访谈记录、课程作业流程图、竞品报告中学生反馈缺失项统计）

二、核心使用场景  
- 触发场景：学生完成《创业基础》课程作业/校内青创赛初筛/孵化营入营申请，需提交≤800字文字版创业想法（非完整BP）  
- 输入：一段自然语言描述（含项目名称、解决什么问题、目标用户、如何赚钱等核心要素，格式自由）  
- 处理过程：系统解析输入 → 分配12个AI委员角色（如“技术可行性委员”“早期用户洞察委员”“财务模型委员”“政策合规委员”等）→ 各委员独立生成带依据的短评（≤3句话）→ 汇总生成共识性诊断+TOP3待优化项  
- 用户期望结果：一份可打印/截图的「评审快照」——不是AI幻觉输出，而是能直接粘贴进作业修改说明、或作为下一次导师面谈的讨论提纲  

三、核心产品路径  
1. 学生粘贴/输入创业想法（纯文本框，无格式要求，支持中文）  
2. 点击「提交评审」→ 系统显示“12位AI委员正在审议…”（加载态≤15秒）  
3. 返回结构化结果页：  
　　• 【共识诊断】1句总结（例：“项目价值清晰，但缺乏最小可行验证路径”）  
　　• 【委员短评】12条独立评论（每条标注委员身份+1个核心质疑/建议+1句依据，如：“市场定位委员：目标用户描述为‘大学生’过于宽泛，建议聚焦‘大三跨专业考研失败转岗群体’，因该群体存在明确求职焦虑与付费意愿（参考2024校招调研Q3）”）  
　　• 【行动清单】TOP3可立即执行的修改项（例：“① 在第二段补充‘如何验证用户真实需求’的具体动作（如：下周访谈5位目标用户并记录拒绝理由）”）  
4. 学生点击「导出反馈」生成PDF（含学校LOGO水印），或点击「重新提交修改版」进入下一轮  

→ 关键断点：  
• 断点1（输入成本）：学生不愿重写/格式化内容 → MVP必须支持任意粘贴，不做字段强制（如不设“目标用户”填空框）  
• 断点2（信任门槛）：学生怀疑AI反馈是否“真有用” → 必须每条委员评论含**可追溯依据**（引用公开数据/课程教材章节/本校往届优秀项目特征），禁用“根据常识判断”类表述  
• 断点3（输出不可执行）：若建议抽象（如“加强商业模式”）→ 直接失效 → MVP中所有建议必须绑定**具体动作+完成标准+时间粒度**（例：“在48小时内设计1个用户验证实验，输出3个假设+1个否证指标”）  

四、MVP最小闭环  
- 必须有：  
　✓ 纯文本输入框（不限字数，但默认提示“建议≤800字”）  
　✓ 12个预设AI委员角色及对应prompt工程（每个角色有固定审查维度+1个权威依据源，如“政策委员=教育部《大学生创业扶持指南》2023版第4章”）  
　✓ 结构化结果页（共识诊断+12条带依据短评+TOP3行动清单）  
　✓ PDF导出（含学校水印，支持打印）  
- 暂不需要：  
　✗ 多轮对话式迭代（如“针对第2条建议再追问”）  
　✗ 学生账号体系/历史记录/版本对比  
　✗ 教师后台管理界面（MVP阶段由教师用学生账号体验，或人工转发PDF）  
　✗ AI委员形象/头像/发言动画（零价值装饰）  
- 人工兜底：  
　✓ 所有12个委员的“依据源”由产品团队预先配置（非实时联网检索），确保100%可验证；若某委员依据源缺失，则该委员角色暂不启用，总数动态降为11→不强求12；  
　✓ 当学生输入明显无效（如纯表情包、<20字、英文乱码），返回固定提示：“请用中文描述你的创业想法，至少50字”，不调用大模型  

五、核心功能  
| 功能 | 服务的用户任务 | 优先级 | 依据 | 验证状态 |  
|------|----------------|--------|------|-----------|  
| 自由文本输入框 | 降低提交门槛，适配学生真实写作习惯 | 核心 | 用户洞察官报告：93%学生用Word草拟，拒绝表单式填写 | 有据 |  
| 12角色AI委员并行评审 | 提供多维视角，模拟真实委员会张力 | 核心 | 竞品报告：现有工具仅提供单维度打分（如“创意分”），学生反馈“像被一个老师批” | 有据 |  
| 每条评论含身份+建议+可验证依据 | 建立信任，让反馈可溯源、可辩论 | 核心 | 教师访谈：“学生只信有出处的批评”；往届优秀项目复盘显示，带教材页码的批注修改率提升3.2倍 | 有据 |  
| TOP3行动清单（含动作+标准+时限） | 将反馈转化为下一步动作，避免“看了但不会改” | 核心 | 课程作业SOP要求“修改说明需列明3项具体行动”，此功能直击交付刚需 | 有据 |  
| PDF导出（带校方水印） | 支持作业提交/面谈材料准备，完成教育场景闭环 | 支撑 | 教务处流程图明确要求“评审材料需归档PDF” | 有据 |  
| 委员角色动态降维（如11人运行） | 保障输出稳定性，避免因单点失效导致整个评审失败 | 支撑 | 技术可行性验证：大模型API超时率≈8%，需容错机制 | 有据 |  
| 多轮提交入口（灰按钮，文案“修改后重新评审”） | 支持迭代，但非首期必需 | 延后 | 用户任务是“首次获得可行动反馈”，非“持续辅导”；延后验证学生是否真会用第二轮 | 需求假设待验证 |  
| 教师后台仪表盘 | 不服务于学生“获得反馈”这一主任务 | 不做 | 项目方提出，但学生无需此功能；机构采购决策不依赖实时数据看板，而依赖试点效果（如“学生修改率”“教师节省工时”） | 明确不做 |  

六、关键交互设计  
- 用户输入：单文本框，placeholder：“用中文写下你的创业想法（比如：我想做一个帮考研失败同学快速转岗的简历优化工具，用户是2024届双非院校毕业生…）”  
- 系统处理：调用12路大模型API（同一输入，不同system prompt），每路输出严格约束为：1身份标签 + 1建议句 + 1依据句（依据句必须含具体来源，如“《创业管理》P142案例”“2023本校就业白皮书Table5”）  
- 用户确认：无显式确认步骤（避免增加路径长度）；加载完成后自动展示结果页  
- 输出结果：一页A4尺寸PDF预览（三栏布局：左=共识诊断，中=12条短评折叠展开式，右=TOP3行动清单加粗标红）  
- 下一步行动：页面底部固定按钮「导出PDF」+「复制反馈到剪贴板」；无其他跳转  

七、功能取舍  
- 本阶段必须做：  
　• 文本输入+12委员并行评审+带依据短评+TOP3行动清单+PDF导出  
- 可以延后：  
　• 修改后重新评审（MVP验证后，若>65%学生在72小时内提交第二版，再上线）  
　• 教师端汇总报表（仅当学校采购时，用人工方式提供周报：如“本周学生共提交XX份，TOP3共性问题为…”）  
　• 语音输入/图片OCR（学生当前99%用键盘输入）  
- 明确不做：  
　• AI委员视频发言/虚拟人形象（项目方提及“增强沉浸感”，但用户任务是“获得可行动反馈”，非“观看表演”；竞品测试显示虚拟人使学生注意力分散，修改率下降22%）  
　• 创业想法自动美化/润色（用户没提“写不好”，只提“不知怎么改”；此功能服务写作任务，非评审任务）  
　• 社区点赞/排名/排行榜（与“获得反馈”零关联；属社交功能，伪需求信号）  
　• 商城/课程/招聘模块（项目原文堆砌，无任何用户证据指向这些任务）  

八、关键产品风险  
- 需求风险：学生可能将系统反馈当作“终审结论”，放弃找教师面谈 → 需在PDF页脚强制添加：“本反馈由AI模拟生成，最终决策请与你的创业导师共同确认”  
- 使用风险：部分学生输入过长（>2000字）导致API超时或输出失焦 → 人工兜底已设“>800字”弱提示，且系统自动截断至前800字（保留语义完整性）  
- 交互风险：TOP3行动清单若建议超出学生能力（如“搭建MVP技术原型”），将引发挫败 → 所有行动项经教育学顾问审核，限定为“48小时内可完成的非技术动作”（访谈/问卷/手绘流程图/竞品截图对比等）  
- 落地风险：12个委员依据源若与本校教学大纲不符，将丧失可信度 → MVP仅启用已获2所试点校教师书面确认的6个依据源（如《创业基础》教材、本校就业白皮书），其余6个角色暂不激活  

九、待验证产品假设  
1. 学生愿为“3分钟获得结构化反馈”改变现有提交习惯（当前多用微信私发教师）→ 验证：在试点校用人工MVP（教师用预设话术模板手动生成12条反馈）测提交率  
2. “带教材页码的建议”比“通用建议”显著提升修改意愿 → 验证：A/B测试两组PDF，一组含页码引用，一组不含，测量72小时内学生修订文档打开率  
3. 教师接受用学生导出的PDF替代人工初评 → 验证：邀请试点校教师用系统反馈直接批改5份作业，记录其补充修改比例与耗时  

十、产品验证建议  
- 验证对象：2所试点校各30名《创业基础》课程学生 + 4名授课教师  
- 验证方式：**人工MVP**（非代码上线）：教师用Excel模板+预设12委员话术库，手动为学生输入生成反馈PDF；全程记录学生从提交到导出的时间、是否修改、是否主动找教师讨论  
- 核心指标：  
　• 学生单次提交完成率（≥90%）  
　• 72小时内基于反馈修改方案的比例（基准线：当前人工反馈下为11%，目标≥45%）  
　• 教师单份初评平均耗时下降幅度（目标：从22分钟→≤8分钟）  
- 通过条件：  
　• 两项核心指标达标，且教师书面确认“愿在下学期用此替代初筛环节” → MVP成立  
　• 仅一项达标，或教师要求增加1项功能（如“导出Word”）→ MVP部分成立，待补证
