【风险审查报告】

一、风险总览  
- 风险计数：致命 3 个 / 高 4 个 / 中 1 个 / 低 0 个  
- 总体判断：存在致命风险，待处置  

二、合规与法律风险  
▶ 风险点（锚定项目做法）：**系统基于大模型API直接上线对外服务，面向高校学生提供生成式AI评审服务，但未说明是否完成《生成式人工智能服务管理暂行办法》要求的备案**。  
→ 等级：致命  
→ 触发条件：项目已“对外服务”（含学生提交想法、AI生成评审意见并返回结果），且该服务属于“向公众提供生成式人工智能服务”。  
→ 潜在后果：未备案即上线运营，可能被网信部门责令暂停服务、下架、通报；若生成内容引发争议（如歧视性评价、错误政策解读），责任归属无备案支撑将显著加重平台责任。具体处罚依据待核验。  
→ 上线前必须完成的动作：**完成国家网信办生成式人工智能服务备案，并在产品界面显著位置公示备案编号**（备案为前置强制义务，非“上线后补”）。  

▶ 风险点：**机构版向学校采购，但未说明是否具备《增值电信业务经营许可证》（ICP证）或《在线数据处理与交易处理业务》（EDI证）等基础电信资质**。  
→ 等级：致命  
→ 触发条件：系统以SaaS形式向高校提供在线评审服务，涉及“通过互联网向用户提供有偿信息服务”，属于经营性互联网信息服务。  
→ 潜在后果：无ICP证即开展经营性服务，违反《互联网信息服务管理办法》，属无证经营，可被通信管理部门责令关闭网站、罚款；影响政府采购合规性及合同效力。具体罚则待核验。  
→ 上线前必须完成的动作：**取得有效期内的ICP许可证（若含支付结算或数据处理功能，需同步评估EDI证必要性）**。  

▶ 风险点：**学生免费使用，但未说明是否建立独立资金账户、是否涉及预收/代收学校采购款后的分账行为**。  
→ 等级：致命  
→ 触发条件：学校按年采购机构版，款项由平台收取后，若存在向AI模型供应商（如大模型API厂商）、评审规则设计方、第三方审核员等进行分账结算，且平台未持牌即归集、划转资金。  
→ 潜在后果：构成“二清”（二次清算），涉嫌非法从事支付结算业务，触碰《非银行支付机构监督管理条例》红线，可能被央行或公安立案调查。具体违法认定与处罚幅度待核验。  
→ 上线前必须完成的动作：**明确资金路径——若平台仅作为技术服务方，须确保学校付款直达模型服务商/合作方账户（即“直付模式”）；若确需平台收款后分账，必须取得《支付业务许可证》或与持牌支付机构签署合法分账协议并嵌入其清分通道**。  

三、数据与隐私风险  
▶ 风险点：**学生提交“创业想法”，内容可能包含个人身份信息（如姓名、学号、学院、联系方式）、商业秘密（技术方案、市场策略）、甚至敏感个人信息（健康科技类项目涉及生物数据、未成年人参与项目等）；但未说明数据收集范围、最小必要性设计、告知同意机制、存储期限与删除路径**。  
→ 等级：高  
→ 触发条件：学生在前端表单中填写/上传文本、图片、PDF等材料，系统未在提交前弹出单独、清晰的数据处理告知书（含目的、方式、保存期、权利行使方式），且未提供便捷的“撤回同意”与“账号注销+数据删除”功能。  
→ 潜在后果：违反《个人信息保护法》第17、47条（告知义务、删除权），导致监管约谈、整改通知；学生投诉或诉讼风险上升；若数据泄露，责任无法以“已告知”抗辩。  
→ 上线前必须完成的动作：**上线前发布独立《学生用户个人信息处理规则》，嵌入提交流程强提示；实现“一键注销+全量数据自动清除”（含数据库、日志、备份）；对创业想法文本中可能含有的身份证号、手机号等字段做前端脱敏提示与后端加密存储**。  

▶ 风险点：**AI委员生成的评审意见可能复现、推断、泄露学生原始想法中的非公开信息（如技术细节、竞品名称、团队成员），形成事实上的“数据反哺”风险**。  
→ 等级：高  
→ 触发条件：大模型API未配置严格的数据隔离与训练禁用策略（如未勾选“禁止用于模型训练”选项），且平台未与API提供商签署数据不出域、不用于再训练的书面协议。  
→ 潜在后果：学生创意被模型记忆并泄露至其他用户提问场景，构成商业秘密侵权与个人信息权益侵害；若涉科研成果或专利构思，可能引发权属纠纷。  
→ 上线前必须完成的动作：**与所用大模型API服务商签署具有法律约束力的《数据安全与模型训练限制补充协议》，明确禁止原始输入数据用于模型训练、微调、增强；在系统后台配置API调用参数强制启用“disable_training”类开关（依厂商文档命名）；定期审计API日志确认未发生训练数据回传**。  

四、内容与安全风险  
▶ 风险点：**12个AI委员模拟真实评审，生成内容包括对创业项目的否定性判断（如“技术不可行”“市场无需求”“团队能力不足”）、价值评判（如“缺乏社会价值”“伦理风险高”），但未说明是否建立内容安全过滤、价值观对齐校准与人工复核机制**。  
→ 等级：高  
→ 触发条件：AI生成评审意见中出现歧视性表述（如针对地域、性别、残障背景团队的贬损）、错误政策引用（如误判“双减”适用范围）、或对敏感领域（AI生成内容、生命科学、金融）做出无依据的合规背书/否决。  
→ 潜在后果：引发学生心理伤害、群体性投诉；若意见被学校采信作为课程评分/孵化资格依据，可能构成教育评价失当；内容违规被网信部门认定为“传播错误价值观”，触发内容下架与约谈。  
→ 上线前必须完成的动作：**部署多层内容安全网关：① 前置关键词与语义规则过滤（屏蔽侮辱、歧视、绝对化否定词汇）；② 后置AI价值观对齐模型（如基于RLHF微调的价值观打分模块）对每条评审意见进行合规性评分；③ 对评分低于阈值的意见强制进入人工复核队列（由高校创业导师或平台合规官终审）**。  

▶ 风险点：**学生提交内容为UGC，平台未说明是否承担违法信息发现与处置义务**。  
→ 等级：高  
→ 触发条件：学生在“创业想法”中夹带违法信息（如涉政隐喻、暴力煽动、盗版资源链接、虚假融资承诺），系统未设置内容初筛与人工巡查机制。  
→ 潜在后果：按《网络信息内容生态治理规定》，UGC平台对用户发布内容负有“先审后发”或“及时处置”义务；未履行将被认定为内容管理失职，面临行政处罚。  
→ 上线前必须完成的动作：**建立“AI初筛+人工抽检”双轨内容审核机制；制定《创业想法内容安全规范》并公示；开通校内辅导员/创业学院教师协同举报入口；留存全部内容日志不少于6个月**。  

五、运营与履约风险  
▶ 风险点：**完全依赖大模型API提供核心评审能力，未说明是否存在API调用失败、响应延迟、输出格式错乱等故障下的降级方案与用户告知机制**。  
→ 等级：中  
→ 触发条件：大模型服务商突发限流、宕机或返回乱码/空响应，系统未配置缓存评审模板、本地规则引擎兜底或明确服务不可用提示。  
→ 潜在后果：学生提交后长时间无反馈，或收到不可读结果，损害信任；若恰逢校内路演截止期，可能引发教学事故投诉。  
→ 上线前必须完成的动作：**部署轻量级规则引擎（如Drools）作为API失效时的备用评审模块（输出标准化提示：“AI委员正在深度思考，请稍候重试”或基于预设维度给出通用建议）；所有接口调用增加超时熔断与错误分类告警；在首页显著位置公示SLA承诺（如“99.5%可用性”）及故障报备渠道**。  

六、伦理与社会风险  
▶ 风险点：**AI委员以“12人委员会”形式呈现，易使学生误认为获得真实专家集体决策，但未披露其AI本质、能力边界与不确定性**。  
→ 等级：高  
→ 触发条件：产品界面未在显著位置标注“本评审由AI模拟生成，不构成专业投资建议或学术评价”，且未提供“查看AI推理过程”或“切换为简化版解释”的交互选项。  
→ 潜在后果：学生过度信赖AI结论，放弃自主思考或盲目修改项目；若因AI误判导致学生放弃优质项目或投入错误方向，引发教育伦理质疑；违反《生成式人工智能服务管理暂行办法》第4条“标识义务”。  
→ 上线前必须完成的动作：**所有评审结果页顶部固定栏强制显示：“【AI模拟评审】本意见由人工智能生成，仅供参考，不替代人类专家判断。点击展开推理逻辑”；默认展开首层推理链（如“基于您描述的技术路径，对比2023年高校专利库中相似方案，发现…”，避免黑箱）**。  

▶ 风险点：**面向高校学生（含大量18岁以下本科生），未说明是否对未成年人设置特殊保护机制**。  
→ 等级：高  
→ 触发条件：系统未识别用户年龄（如未对接教务系统学籍数据或未要求实名认证），亦未对未成年用户屏蔽高风险提示（如“融资失败率92%”“团队能力不足”等可能引发焦虑的绝对化表述）。  
→ 潜在后果：违反《未成年人保护法》第71条及《生成式人工智能服务管理暂行办法》第10条，对未成年人应“提供适龄化服务”“避免诱导沉迷或造成心理伤害”；若引发学生自伤事件，平台注意义务缺失将成追责焦点。  
→ 上线前必须完成的动作：**接入教育主管部门认可的实名核验通道（如学信网API），对18周岁以下用户自动启用“关怀模式”：屏蔽负面强度>阈值的措辞、强制插入心理支持提示（“创业是长期探索，一次评审不代表终点，点击获取校内心理中心预约入口”）、限制单日提交频次以防沉迷**。  

七、落地与资质风险  
▶ 风险点：**拟进校园，但未说明是否符合《教育部等六部门关于规范校外线上培训的实施意见》及地方教育部门对“进校应用”的准入要求（如数据本地化、源代码审计、等保三级备案、与学校签订数据安全责任书）**。  
→ 等级：高  
→ 触发条件：学校采购机构版并部署于校内网络环境，或要求数据存储于校方服务器，而平台当前架构为公有云SaaS，未提供私有化部署选项或等保测评报告。  
→ 潜在后果：无法通过学校信息中心安全准入审查，导致采购流产；若强行接入校内网络但未达等保二级（高校普遍要求等保三级），将违反《网络安全法》第21条，学校IT部门有权阻断连接。  
→ 上线前必须完成的动作：**完成等保二级备案及测评（若仅服务单校可起步于此）；提供私有化部署包及配套运维手册；与首批合作高校签署《数据安全与责任划分协议》，明确数据主权归属学校、平台仅获有限处理授权**。  

八、红线清单（致命与高风险按优先级排序）  
① **未完成生成式人工智能服务备案，不得对外提供任何AI评审服务**（致命｜合规）  
② **未取得ICP许可证，不得以经营性方式向学校收取机构版采购费用**（致命｜合规）  
③ **未解决资金路径问题（直付模式未落实或无支付牌照），不得收取任何学校采购款项**（致命｜合规）  
④ **未上线学生个人信息处理规则并实现“一键注销+数据自动清除”，不得接收学生创业想法提交**（高｜数据）  
⑤ **未部署AI内容安全网关（过滤+价值观评分+人工复核），不得向学生返回AI生成的评审意见**（高｜内容）  
⑥ **未在评审结果页强制标识“AI模拟”并展开基础推理逻辑，不得展示任何评审结论**（高｜伦理）  
⑦ **未对接实名核验并启用未成年人关怀模式，不得向18周岁以下学生开放服务**（高｜伦理）  

九、证据缺口  
① **备案状态缺失**：是否已启动网信办生成式AI备案？是否取得受理回执？需提供备案进度截图或官方回执。  
② **资质现状不明**：ICP许可证是否已申请？若未申请，是否已委托代理机构启动？需提供许可证号或代理协议关键页。  
③ **资金路径未披露**：学校采购款最终流向何处？是否与大模型API商直连结算？需提供资金流示意图及与各方的合同关键条款（付款主体、开票方、结算周期）。  
④ **数据协议空白**：是否与大模型API提供商签署数据不出域协议？需提供协议扫描件或法律意见摘要。  
⑤ **等保进展未知**：是否已开展等保测评？是否取得等保二级/三级备案证明？需提供等保备案号及测评报告封面页。
