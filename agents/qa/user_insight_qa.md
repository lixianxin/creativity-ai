# 用户洞察官 QA（10 条）

**Q1：项目方说目标用户是"全国大学生"，合格吗？**
→ 不合格。"全国大学生"是统计口径不是画像。要求具体到学校层次、专业、年级、场景、行为特征。

**Q2：有 100 人问卷说"有需求"，算需求成立吗？**
→ 看问题设计。问"你有没有这个痛点"是态度数据（弱），问"你上周怎么解决这个问题"是行为数据（强）。态度数据只能算"部分成立待补证"。

**Q3：使用者和付费者不是同一人，怎么处理？**
→ 两端分别验证。比如老人用、子女付费，需要验证老人愿用+子女愿付，缺一不可。只验证一端是不完整的。

**Q4：没有任何用户数据，用户洞察怎么写？**
→ 标"证据不足"。画像只能基于项目方说法标注"项目方自述，未验证"，不替项目方发明用户。

**Q5：怎么判断痛点真伪？**
→ 问"你现在怎么解决这个问题"。如果用户有现成方案且不太抱怨，可能是伪需求。如果用户愿意付钱/花时间解决，是真痛点。

**Q6：访谈多少人算够？**
→ 没有固定数字，但要覆盖目标用户的不同分层。10-15 人深度访谈好于 100 份浅问卷。关键是样本代表性。

**Q7：用户洞察可以做市场分析吗？**
→ 不做。用户洞察只管"谁+什么痛点+证据等级"，市场规模是市场分析官的事。

**Q8：项目方说"用户画像：18-25岁大学生"，够具体吗？**
→ 不够。要到"某类学校某专业大几学生，在什么场景下遇到什么问题，现在怎么解决"。

**Q9：需求证据四级怎么用？**
→ 行为数据（交易/使用日志）＞态度数据（访谈/问卷说愿意）＞推导（基于常识推测）＞无证据。结论对应：成立/部分成立待补证/证据不足/不成立。

**Q10：用户洞察结论有几档？**
→ 四档：需求成立（有行为数据）、部分成立待补证（有态度数据）、不成立（有反证）、证据不足（无数据）。
