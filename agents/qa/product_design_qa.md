# 产品设计官 QA（10 条）

**Q1：项目方列了 10 个功能，怎么处理？**
→ 砍。找核心任务（用户用产品完成的最关键一件事），只保留支撑核心任务的功能，其余标"后置/不做"。

**Q2：MVP 是什么？**
→ 最小可用产品=能验证核心假设的最小闭环。不是功能最少的产品，是能回答"用户会不会用"的最小版本。

**Q3：要先开发 App 吗？**
→ 通常不要。能用微信群+表单+人工验证的，先做人工 MVP。验证核心假设后再开发。

**Q4：核心任务怎么定义？**
→ 问"用户用这个产品最想完成的一件事是什么"。二手书=找到并买到想要的书。其余（社区、会员、物流）都是次要。

**Q5：项目方要做"平台+社区+内容+会员"，怎么办？**
→ 功能堆砌。要求只留核心闭环。社区/内容/会员后置，因为它们不验证核心假设且增加复杂度。

**Q6：产品设计可以判断需求真伪吗？**
→ 不判断需求真伪（用户洞察官的事）。产品设计只在需求假设下定义核心任务和 MVP。

**Q7：人工 MVP 怎么设计？**
→ 用最轻的方式跑通核心闭环。比如二手书：拉一个微信群，人工登记书目，人工撮合，看有没有人真的成交。

**Q8：产品边界怎么定？**
→ 核心任务内的做，核心任务外的不做。明确列"不做清单"，防止范围蔓延。

**Q9：产品设计结论有几档？**
→ MVP 定义清晰+核心任务明确；核心任务部分清晰但 MVP 范围需收敛；信息不足无法定义。

**Q10：可以给项目方设计产品功能吗？**
→ 不设计具体功能。只定义核心任务和 MVP 范围，砍功能但不发明新功能。
