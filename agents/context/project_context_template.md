# 创想∞ AI创业委员会 —— 统一项目上下文模板（V1.0 固化）

本模板是 12 个 Agent 之间唯一的数据契约。
- 上游 Agent 的输出按本模板归档；下游 Agent 从本模板读取，不得自行脑补未提供字段。
- 项目方未提供的字段一律写“未提供”；Agent 未产出报告时写“未生成”。
- 任何 Agent 不得伪造本模板中的数据；项目方没给的数字保持“未提供/待验证”。

---

## A. 项目方填报区（项目基础信息）

```text
项目名称：
项目描述：（项目方原话，不改写）
目标用户：（项目方原话，不改写；未提供写“未提供”）
核心痛点：
解决方案：
商业模式：（谁付费、收多少、怎么收）
当前阶段：（想法/调研中/试点中/运营中，附已有证据清单）
```

## B. 专家报告区（各 Agent 产出，按链归档）

```text
【市场链】
用户洞察报告：        （用户洞察官）
市场分析报告：        （市场分析官）
竞品分析报告：        （竞品分析官）

【产品商业链】
产品分析报告：        （产品设计官）
商业模式报告：        （商业模式官）
增长运营报告：        （增长运营官）

【风险决策链】
财务可行性分析报告：  （财务分析官 V1.0，已实测通过）
风险审查报告：        （风险审查官）
红队审查报告：        （红队质疑官 V1.0，已实测通过）

【决策层】
项目成熟度评估：      （项目评审官）
委员会阶段结论：      （创业总指挥 V1.0，已实测通过）
路演答辩结果：        （路演答辩官）
```

## C. 状态约定

- 报告状态取值：`已生成` / `未生成`。
- Agent 结论取值：
  - 财务分析官：数字成立 / 数字倾向不成立 / 当前无法可靠计算
  - 红队质疑官：暂缓通过 / 有条件通过 / 通过
  - 创业总指挥：暂缓通过 / 有条件通过 / 通过（+ 项目阶段：想法验证 / 方案修正 / 路演准备 / 可进入路演）
- 所有 Agent 共同铁律：不虚构数据、不替项目方设计方案、信息不足明示“信息不足/待验证”、输出固定报告格式。

## D. 最小闭环调用顺序（V1.0 已实测）

```text
项目基础信息
 → 财务分析官 → 红队质疑官 → 创业总指挥
```

## E. 完整委员会目标顺序（Phase 4 扩展中）

```text
项目基础信息
 → 用户洞察 → 市场分析 → 竞品分析
 → 产品设计 → 商业模式 → 增长运营
 → 财务分析 → 风险审查
 → 红队质疑
 → 创业总指挥
 → 项目评审
 → 路演答辩
```

注：各 Agent 必须能独立使用（只给项目基础信息也能产出本专业报告）；
串联时下游 Agent 读取上游报告但不得重复其专业分析。
