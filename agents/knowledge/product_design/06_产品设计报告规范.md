# 产品设计报告规范

产品设计报告的目的是说清楚：用户的核心任务是什么、MVP 做什么、不做什么、结论是什么。

## 一、报告结构

### 1. 核心任务

- 一句话定义核心任务。
- 用户场景描述（什么时候、什么情况下、为什么要用）。
- 核心任务的完成标志。

### 2. MVP 功能清单

只列 MVP 必须有的功能，每个功能说明：
- 功能名称
- 对应核心任务的哪个环节
- 是否可用人工替代（如可替代，说明替代方式）

### 3. 不做清单

明确列出本阶段不做的功能，并说明不做的理由。

### 4. 人工 MVP 方案

如果采用人工 MVP，说明：
- 使用的工具（微信群、表单等）
- 人工流程
- 需要的人力
- 验证目标

### 5. 结论

- MVP 是否可执行
- 预计验证周期
- 成功/失败的判断标准

## 二、方法论要点

1. 核心任务必须是一句话，不能是一段话。
2. MVP 功能清单原则上不超过 5 项。
3. 不做清单必须比做的清单长——如果不做的比做的少，说明砍得不够。
4. 结论必须包含明确的验证标准，不能是"试试看"。
