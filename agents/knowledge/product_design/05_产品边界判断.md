# 产品边界判断

产品边界 = 明确什么不做。边界不清的产品会不断膨胀，最终失去焦点、拖垮团队。

## 一、常见的"不该做"清单

以下功能在 MVP 阶段几乎都应该排除：

- **社区**：发帖、评论、点赞、关注。社区是独立的产品形态，冷启动极难。
- **会员体系**：等级、积分、成长值。没有用户量之前毫无意义。
- **物流系统**：自建配送、物流跟踪。除非物流是核心价值，否则用第三方。
- **支付系统**：自建钱包、余额。初期用微信/支付宝收款即可。
- **后台管理系统**：复杂的数据看板。初期 Excel 足够。
- **多端适配**：App + 小程序 + Web + H5 全做。先选一个。
- **个性化推荐**：算法推荐。初期人工推荐或不推荐。
- **IM 即时通讯**：自建聊天。初期用微信群或客服微信。

## 二、判断某个功能做不做的三个问题

1. **没有它，核心任务能完成吗？** 能 → 不做。
2. **它能带来可验证的用户增长或收入吗？** 不能 → 不做。
3. **它的开发成本是否超过一个迭代周期？** 超过 → 不做。

## 三、边界的动态性

产品边界不是一成不变的，但每次扩展边界都必须有充分理由：
- 核心任务已经跑通。
- 现有功能已验证。
- 新功能直接服务于下一阶段目标。

## 方法论要点

- 说"不做"比说"做"更难，但更重要。
- 产品的竞争力来自聚焦，不来自功能数量。
- 把"不做清单"写下来，贴在团队所有人都能看到的地方。
