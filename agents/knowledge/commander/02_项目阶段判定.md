# 项目阶段判定

总指挥的首要输出是判断项目当前处于哪个阶段。不同阶段的核心任务完全不同，禁止跨阶段行事。

## 四阶段判据

### 阶段一：想法验证
**判据**：只有一个想法，没有产品原型，没有用户数据。
**核心任务**：验证需求是否真实存在。
**不该做**：开发完整产品、大规模投入、谈融资。
**通过标准**：有 10+ 目标用户访谈证实痛点存在，且现有替代方案不满意。

### 阶段二：产品验证
**判据**：有 MVP 或原型，有少量种子用户，但未验证付费。
**核心任务**：验证产品能否解决痛点，用户是否愿意持续使用。
**不该做**：大规模推广、重金投放、扩张团队。
**通过标准**：核心功能使用率达标，留存率有数据支撑，用户主动推荐。

### 阶段三：商业验证
**判据**：产品有付费用户，但单位经济模型未跑通。
**核心任务**：验证 LTV/CAC、回本周期、盈亏平衡。
**不该做**：盲目扩张用户规模、烧钱换增长。
**通过标准**：LTV/CAC ≥ 3，回本周期在可接受范围内，有稳定获客渠道。

### 阶段四：规模扩张
**判据**：单位经济模型成立，获客渠道可复制。
**核心任务**：放大已验证的获客渠道，扩大市场覆盖。
**不该做**：同时尝试多个新方向、改变核心产品。
**通过标准**：规模化后单位经济不恶化，现金流健康。

## 阶段判定输出

必须明确给出当前阶段，并说明依据（引用哪个 Agent 的哪份报告）。若各报告结论冲突，按证据冲突仲裁规则处理。
