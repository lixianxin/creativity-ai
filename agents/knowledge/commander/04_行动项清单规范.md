# 行动项清单规范

总指挥输出的行动项必须是**3 个**，不多不少。每个行动必须可执行、可验证，禁止空话。

## 行动项三要素

每个行动项必须包含：

1. **行动内容**：具体做什么，用动词开头。
2. **负责方**：谁来做（项目方 / 某个 Agent / 需外部资源）。
3. **验证标准**：什么结果算完成，必须可量化或可判断。
4. **deadline 性质**：这个行动的时间紧迫度。

## deadline 性质分类

- **紧急（本阶段内）**：不做就无法进入下一阶段。
- **重要（下一阶段前）**：本阶段可启动，下一阶段前必须完成。
- **持续（贯穿多阶段）**：需要长期跟踪，不是一次性任务。

## 行动项示例

### 好的行动项
- **行动**：完成 20 份目标用户付费意愿访谈。
- **负责方**：项目方（用户洞察官提供访谈提纲）。
- **验证标准**：访谈中明确表示愿意付费的用户 ≥ 8 人，且给出可接受价格区间。
- **deadline 性质**：紧急（商业验证阶段卡点）。

### 坏的行动项（禁止）
- "加强用户运营"——无具体内容、无验证标准。
- "提升产品体验"——不可量化。
- "寻找更多用户"——无数量、无渠道、无标准。

## 数量规则

- 严格输出 3 个行动项。
- 3 个行动必须围绕核心矛盾展开，不发散。
- 若核心矛盾只需 1-2 个行动，其余行动填支撑性任务，但不得凑数。
