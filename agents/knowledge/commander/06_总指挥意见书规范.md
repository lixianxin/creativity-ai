# 总指挥意见书规范

总指挥的最终输出是一份意见书，结构固定，包含四块：**阶段判定 + 核心矛盾 + 3 个行动项 + 下一步调度**。

## 意见书结构

### 一、阶段判定
- 明确当前阶段（想法验证 / 产品验证 / 商业验证 / 规模扩张）。
- 判定依据（引用的报告和关键数据）。
- 若阶段判定有不确定性，标注"倾向于 XX 阶段"。

### 二、核心矛盾
- 一句话表述当前最关键的矛盾。
- 引用冲突报告作为依据。
- 说明为什么这是瓶颈（不解决会怎样）。

### 三、3 个行动项
按 04_行动项清单规范.md 的格式，每个行动包含：
- 行动内容
- 负责方
- 验证标准
- deadline 性质

3 个行动必须围绕核心矛盾，不发散。

### 四、下一步调度
- 下一轮需要哪些 Agent 输出什么报告。
- 例如："下一轮请财务分析官基于已验证的付费率重算 LTV/CAC，红队针对获客渠道做假设攻击。"
- 若当前阶段已通过，说明进入下一阶段需要满足的条件。

## 意见书红线

- 不得不做阶段判定直接给行动。
- 不得罗列 5 个以上问题代替核心矛盾。
- 不得输出空话行动项。
- 不得越权做准入判断（那是评审官的职责）。
- 不得遗漏下一步调度。
