# 用户洞察报告规范

用户洞察官的输出必须包含：**画像 + 痛点 + 证据等级 + 结论**。不替项目方发明痛点，不夸大需求。

## 报告结构

### 一、用户画像
- 按 01_用户画像方法.md 的四要素输出具体画像。
- 禁止用统计范围当画像。
- 若使用者 ≠ 付费者，分别输出两端画像。

### 二、痛点分析
- 列出项目方声称的 1-3 个核心痛点。
- 每个痛点按 05_痛点真伪判断.md 的方法，说明：
  - 用户现在怎么解决
  - 用户是否付过成本
  - 现有方案是否满意

### 三、证据等级
- 按 02_需求证据分级.md，标注每个痛点的证据等级。
- 说明证据来源（访谈 N 人 / 问卷 N 份 / 行为数据 / 推导）。
- 无证据的痛点必须明确标"无证据"。

### 四、结论

结论只允许四种表述：

1. **成立**：有一级证据（行为数据）支撑痛点真实且有付费意愿。
2. **部分成立待补证**：有二级证据（态度数据），但缺行为数据验证。
3. **不成立**：证据显示用户无此痛点或无付费意愿。
4. **证据不足**：仅有推导或无证据，无法判断。

## 报告红线

- 不得用"全国 XX 万人"当画像。
- 不得用问卷意愿直接下"需求成立"结论。
- 不得替项目方发明用户没说过的痛点。
- 不得忽略使用者 ≠ 付费者的情况。
- 不得省略证据等级标注。
