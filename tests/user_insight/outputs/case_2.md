# 用户洞察官案例2：AI学习助手-所有学生+免费广告

- 平台：deepseek / deepseek-v4-flash
- 耗时：21.1s，tokens：1582+2303

## 输入

项目名称：AI学习助手
项目描述：我要做一个AI学习助手，面向所有学生，完全免费，未来靠广告盈利，预计第一年100万用户。
目标用户：所有学生
核心痛点：未提供
解决方案：AI学习助手
商业模式：免费+广告
当前阶段：想法阶段

## 用户洞察输出

【用户洞察报告】

洞察结论：证据不足
一句话依据：项目方未提供核心痛点；用户定义仅为“所有学生”这一统计口径；项目处于想法阶段，没有任何行为或态度级证据支撑需求。

一、用户画像清晰度
- 项目方定义：“目标用户：所有学生”
- 洞察：你定义的“所有学生”不是用户画像，是统计口径。从K12、中专到大专、本科、研究生，学习场景、任务类型、每日可用时间、购买力与自驱力差异极大。这个范围无法用来识别具体人群、设计触达方式，也无法检验需求真伪。当前清晰度为“几乎为零”。

二、用户分层与种子用户
- 核心用户 / 次要用户：材料未提供任何分层依据；“所有学生”无法划分核心、次要、旁观者。
- 可落地的种子用户假设：无法从材料中确定，待验证。要形成可落地假设，至少需要具体到“某学段×某类学校/升学阶段×某个学习任务卡点”，比如“大二通过四级后的六级备考学生”或“高二物理长期低于70分的学生”。但项目方未提供上述场景，当前无种子用户。

三、使用者与付费者
- 使用者：按你的定义是学生。
- 付费者/决策者：按你的商业模式（免费+广告），直接付费者不是学生本人，而是广告主；学生的“付费”体现为时间、注意力和行为数据。
- 分离风险：存在。你需要在“免费工具先把学生留住并形成高频使用”成立后，广告模式才有前提；但材料里没有任何证据表明学生会在无明确痛点的前提下持续使用该产品。

四、核心任务与痛点（JTBD）
- 场景与任务：未提供。“AI学习助手”没有对应到任何一个具体任务，例如完成作业、备考、查漏补缺、笔记整理、错题复习等皆未说明。
- 痛点频率与强度：待验证。无任何证据表明该痛点每天、每周出现，也无证据表明不解决会造成什么后果。
- 现有不满的具体内容：未提供。看不到“现有方式哪里不够好”的描述。

五、用户当前行为路径
- 用户现在如何完成该任务：未提供。这是关键缺口。任何真实学习任务都存在学生当前的做法：看教材、问同学、搜题App、刷网课、问老师、抄答案等。项目方没有给出这条路径，就无法证明用户“现在有未被满足的需求”。

六、需求证据质量
- 现有证据清单：
  1. “预计第一年100万用户”——项目方主观判断，无任何数据支撑，证据等级为“主观判断”。
  2. “面向所有学生，完全免费，靠广告盈利”——商业模式假设，无任何用户反馈，证据等级为“主观判断”。
  3. 核心痛点未提供——无访谈、无问卷、无行为数据。
- 证据局限：没有任何样本量、抽样方式、访谈来源可评估；当前全部证据停留在“项目方认为”层面。

七、用户维度关键疑点
- “目标用户：所有学生”——用户定义过宽。这个群体没有共用同一学习任务和行为场景，无法判断谁是你的用户。
- “核心痛点：未提供”——没有痛点假设，需求不成立也谈不上验证。
- “AI学习助手”——解决方案表述抽象，无法反推出用户要完成的任务，因此无法判断用户是否真的会使用。
- “完全免费、靠广告盈利”——使用者（学生）与付费者（广告主）分离。该链条成立的前提是学生高频、长期使用；但目前没有证据说明学生会为一个说不清痛点的AI助手持续掏出注意力。

八、必须补充的用户研究（按优先级）
① 在5个具体人群中进行小样本半结构化访谈（每个群体3～4人，共15～20人）：初二学生、高一/高二学生、非“985”高校的大二学生、考研二战者、大专升本科备考者。访谈任务围绕“过去两周你最头疼的学习任务是什么、当时是怎么解决的、卡在哪一步”，全程不提前提“AI”。目标是把“所有学生”压缩到具体学段＋具体任务。
② 针对访谈中浮现的高频任务，挑选一个真实场景（如“期末高等数学复习”或“考研英语真题精读”），请5～10名学生现场演示他们现有的完成方式，记录：用什么工具、每星期花多少时间、卡住时的处理办法、放弃或凑合的时刻。这是拿到行为级证据的关键一步。
③ 选一个你认为最可能成立的学习任务，做一个不加任何功能的简单“使用意愿小测试”：向该人群展示一段页面说明，只询问“是否愿意留下邮箱、加入等待名单”。看真实留存行为，不断言“大家口头说需要”。如果连等位邮件都不愿留，说明痛点的强烈程度不足。
