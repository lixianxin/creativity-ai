一、增长目标
- 当前阶段：产品原型阶段（MVP已完成，2所学校创业学院老师口头表示感兴趣，尚未有正式付费试用/采购）。
- 核心增长目标：验证“院系教师场景下的学生激活”，而非泛流量获客。本阶段唯一堵点在于：在真实教学/筛选场景中给学生一个强任务动机，并确认学生能完成“提交→收到有价值报告”→“教师感知到筛选价值”。

   （注：必须有真实去重、无幻觉、高多智能体价值的报告达成率，才能推动后续 B 端采购；盲目拉新到 10 万 DAU 对 2B SaaS 毫无意义，只会放大 API 成本与幻觉差评。）

- 核心增长问题：把产品给1位试点老师、1个班的学生用，学生完成第一次提报并生成报告的激活率是多少？教师是否愿意把这套流程写进下一次课程/大创筛选？

二、目标用户入口
- 目标用户：（引用用户洞察官结论）有真实创业想法/被课程要求提交创意的在校大学生（C端，免费）；高校创业学院及创业课程教师（B端付费方）。
- 主要触达场景：不是“刷抖音看到广告”的偶遇场景，而是**老师布置作业 / 大赛报名要求提交商业计划书（BP）/ 大创项目申报步骤中的强任务场景**。学生此时不是“闲逛者”，而是“正被逼着交一份完整项目书”。
- 首次接触渠道：**校内创业课程系统 / 教师微信群 / 课程作业发布入口（B2B2C 层层下传）**。
- 渠道依据：2所学校教师已口头感兴趣（记为 B 端线索）；B端教师是唯一掌握“时间+任务分发+评价权”的守门人，他们的指令即“下个周日前提交到 AI 报告平台”的天然入口。线下纯C端拉新（教学楼海报）对“提交一份完整BP”的完成率极低，渠道匹配度弱，标【增长假设，待验证，且不作为本阶段主渠道】。

三、获客路径
触达 → 点击/进入 → 首次体验 → 激活 → 留存 → 传播
（逐环填写，断点显式标注）

- 触达：试点学院教师对班级学生说“把项目方案提交到 AI 创赛平台完成第一轮初筛”。
- 点击/进入：学生点击教师发在微信群/课程平台的链接注册登录。
- 首次体验：填写基础信息 + 输入项目名称和项目描述。
- 激活：系统生成《12人专家委员结构化审查报告》，其中包含至少一条让学生觉得“这个AI没有白用”的针对性质疑或可执行修改建议，并成功下载报告提交给老师。
- 留存（C端）：第一次使用后就进入 B端教学节奏，下一次启动取决于“下一节课/第二轮修改/大赛报名更新需求”。如果这是一次性提交，则天然无留存。
- 传播（B端教师）：教师看到报告的有效辅助筛评结果，在教研组群分享 / 告知兄弟学院，形成教师间口碑传播。
- **断点标注**：
  1. 学生填完创意 →  点击“评估” → 若多智能体输出超时 / 报告含糊不清，直接流失（首轮留存卡点）。
  2. 学生下载报告 →  若报告只像“通用模板文字缝合”，学生判定“这不如找学长问”，激活失败。
  3. 教师筛选 →  若教师看完报告仍需人工补充大面积漏审，无穿透力，B端采购无望。

四、首次激活
- 什么行为算激活：一个可观测动作：**学生成功提交一个完整创业项目描述，并在 5 分钟内收到该项目专属的、包含 3 条以上针对性批判意见和 1 条可替换的具体修改建议的报告，且点击“下载/分享给同伴”。**（区别于‘拿到一份内容通用的AI安慰语’。）

- 用户第一次获得的核心价值：一夜之间获得“12个专业角度挑毛病”的真实模拟董事会评审（跨专业视角的质疑），以及为满足“老师/大赛要求”而需修改的锦囊。

- 激活障碍：
  1. 学生写“我有一个好主意，想做个APP”，AI无法基于无信息含量描述输出具体审查 —— 需设计结构化引导填写（痛点、人群、竞品、验证方式），否则“弱输入→弱输出”体验崩溃。
  2. 生成等待时间失控。
  3. 多智能体之间互相冲突、无一致性的报告会让用户失去信任。
  4. 报告与通用网文“批发联想”撞车，无学校专属/赛道识别深度。

- 优先解决的断点：首先确保在 30 个 100-300 字的粗糙创意样本上能真实跑出 **“能挑出实质逻辑漏洞”的报告**，其次才是获客。警惕“输入垃圾，输出垃圾”的上线体验（被 AI 幻觉叠加放大）。

五、留存逻辑
- 用户为什么回来：C端——不是天天用；只有当创意迭代、要交作业、要报名大赛时才会二次进来。B端——教师按授课章节、赛程节点每周/每轮要求提交，为学生制造下一次回来的“场景钟表”。
- 下一次使用场景：1）大学生创意从“最初一稿”到“千锤百炼的参赛终稿”；2）教师批改阶段要求修改二次提交。
- 留存触发：
  - 人工触发：教师本周布置第二轮 BP “基于AI报告修改后重交”；
  - 系统触发（辅助留存，非留存本质）：在报告末尾往用户邮箱/微信推送“22个评委提到了‘你的竞品分析为零’，需要我帮你看竞品吗？”的反问式推送；
  - 赛事触发：链接到“互联网+”等大赛关键节点前的辅助自查。
- 流失原因：一次性作业完成，报告结论对真实赛道毫无帮助；学生重新出发的项目没有继承/打磨工具，场景终结，随学期结束流失（这是大学生赛道产品的宿命：需要 B端教师按学期/按课程二次增购复用，而非指望 C端学生自发高频回访——标【增长假设，待验证】）。

- 待验证假设：教师会把“AI批改结果”接入课程线上系统作为计分依据——如果该假设不成立，本产品 C端粘性靠“新作业+新比赛+新学院同学”循环产生，而非存量留存。

六、传播机制
- 用户为什么愿意分享：学生把“项目通过AI专家委员会终审挑战”的证书/经历用于求职、保研、参赛，但**直接分享项目原文=商业隐私裸奔**；教师获得可展示的“选拔效率提升”，愿意做案例分享。
- 分享什么：学生分享截图版报告封面/成绩荣誉贴纸（不含详细BP原文）；教师分享一页脱敏的班级筛查维度对比图。
- 分享给谁：学生分享给自己的目标公司/档案材料；教师分享给兄弟院系创新创业负责人/校领导。
- 分享后的新用户入口：校领导看到后预算审批；兄弟教师点击链接注册试点。
- 是否存在自然增长：**当前不存在C端自然增长飞轮**。学生没有持续产生可分享物（项目未获奖前无高光时刻），且涉及隐私，直接转发原 BP 是高暴露风险。该产品的自然增长点只能是“教师版的1人试用→同事好奇→申请试用→批量激活”的 B 端飞轮，目前在试点阶段完全依赖教师为本人教学有效性与晋升成果主动试用产生的示范性口碑。明确：无用户自发爆点。

九、增长风险
- 渠道风险：教师口头意愿意味着“有耐心配合试用”，并不等于学校预算立项。B2B销售周期长过C端，常保两所学校全部变口头无粘性，校方因缺少排课/经费/IT支持而不采购。
- 激活风险：学生对 AI 生成物不信赖（觉得是通用型 ChatGPT 包装），一旦看出“12人委员会实际上并没有审查我的个性化 MVP，只是在复制套路话”，激活即死刑。
- 留存风险：课程结束 = 一次任务终结；春季大创报名结束 = 自然场景消失。学生无绑定事件，且真正带出的“白嫖”会使下一年度学校采购意愿反向下降（预期一个工具但得到一次性产品）。
- 传播风险：让学生把原始 BP 作为公开件到处转发会导致泄密/被投诉社区审计；如被恶意乱回带节奏，会被直接定性为刷单/违规。
- 平台依赖风险：多智能体所有报告基于单一大模型 API。若 API 审核合规、断连不可用，或大模型知识库幻觉拉低审查浓度，影响教师持续信任。
- 补贴/活动依赖风险：当前无补贴计划——尽量避免。如有在校生“免费赠一个月专家委”刺激注册，必须与班级激活、作业完成率、教师增购三项指标分开计算，不混同为“爆量成功”。（学生免费是模式设计成假象，不代表增长能力自带免费飞轮）

十、最小增长验证
- 最小实验：仅对“某学校一门 2 学分的创业课 30 名学生”做闭环实验。
- 样本对象：教学班级（不用所有有想法的在校生）总量 30 人，外加创业课老师的课堂教学记录。
- 验证周期：2 周（1 周“首次报告生成+初稿”，1 周“按报告改第二稿并提交”）。
- 核心指标：学生“真实提交了文字项目描述”的人数 / 全班人数；AI 报告被下载次数；按报告修改条数（学生截图或重提的第二稿差异）占全班比例。
- 通过条件/停止条件：
  - 通过：≥16/30 人获得真报告且完成第二轮修改；带班老师主动对全班说“这份报告比我逐一批注高效且视角全”。
  - 停止条件：14 天内不到 8/30 名学生完成初稿；或学生反馈中“格式花哨但像ChatGPT生成”“对我的机器人餐厅建议没有引用任何真实校园供应链信息”“4篇内容几乎一样”等关键词出现（包含一项即停止扩大使用，立刻回炉产品报告质量和交互），无论注册量多少，不进入大规模投放。

十一、增长结论
增长路径部分成立，待补证。

在“学校课程任务场景”这一个入口下，产品路径可画通（B 端教师搭台，C 端学生有具象任务补认知），激活事件（首份点名的报告）清晰可测，已获得 2 所学校的教师真实接触线索——这属于“有靠山的场景候补入口”。但以下三个环节依然严重缺少实证：①首轮真实学生注册后，提交完整描述的比例与报告质量评价；②教师会不会愿意主动要求该流程运用于下一轮大创申报；③只要班级结束/赛事结束，教师无后续采购通道，该平台将沦为一次性作业批改造水器，B2B续费的价值并不由C端学生注册量拉动，只由学校多学期排课与大赛承办角色拉动。换言之，当前不存在稳定自然获客飞轮。若仅凭“2位老师感兴趣+全网发波推文”就判定可豪赌大规模投放——这是只能换来注册量的伪增长，应拒绝安排。第二阶段的核心是让30名学生的两个周记录成为说服学校完成第一次采购的证据——用报告性能牵引院校通道复购。
