# Run3 红队审查输出

## 输入
我要做一个面向本校考研学生的寄宿自习室预约与拼团平台，已访谈120名备考学生，68人表示愿意每月付300元买固定座位，目前学校周边3家自习室空位靠微信群登记、经常抢不到，我打算先做微信小程序，向自习室抽佣10%。

## 输出

【红队审查报告】

审查结论：暂缓通过

致命问题：1个
高风险问题：3个
一般问题：1个

核心漏洞：

①【商业假设｜致命】
- 攻击：你声称“向自习室抽佣10%”，但自习室目前的状况是“空位靠微信群登记、经常抢不到”。这意味着自习室本体不缺客流、不存在获客难问题。当你的平台无法给这些满座的B端自习室带来“新增售卖”，他们为什么要为每个座位每月支付10%（约30元）的系统服务费？如果自习室只需要解决“登记乱”，他们自己拉一个在线表格或使用微信的预约小程序，成本远低于每月每个座位的30元持续抽佣。你的收入建立在B端一种“非刚性需求”上，却宣称C端有付费意愿，这是商业链条断裂。
- 待验证：三家自习室各自的真实空置率/满座率；三家自习室是否愿意为“现成的预约功能”按月支付每座位10%佣金，实际访谈B端商家数据。

②【用户假设｜高风险】
- 攻击：你声称“访谈120名备考学生，68人表示愿意每月付300元”。这只是一个态度数据，不是行为数据。样本量小且未说明抽样方式——120名人是否包含此前从未付费进过自习室的人？备考学生往往只说“要是有位子就好了”，你问“要固定位子”，他们可能把300元当做购买“确定性”的价格而不假思索地同意。但这批人是否愿意持续每月掏出300元，取决于真实支付的可支配生活费数据，你未提供。
- 待验证：该群体过去6个月实际购买自习座位的消费记录与留存情况；120人中多少人近期实际使用过付费自习服务。

③【需求假设｜高风险】
- 攻击：你默认“自习室空位靠微信群登记且经常抢不到”是一个平台级痛点，但这更像是一个“排队效率”问题。如果常态化满座，那核心矛盾是供给不足，你没有新增供给，只优化了排队方式，用户并不真的解决“抢不到座位”的问题，只是换了个地方抢。况且，用户现在的解法——提前去微信群接龙、蹲点刷消息——成本很低，你描述的“痛点”是否紧急到让用户每月额外多付300元？
- 待验证：目标学生所在学校的自有图书馆免费座位数量与高峰时段满座率；用户目前解决“抢不到位”的平均耗时和失败频率。

④【竞争假设｜高风险】
- 攻击：你声称“目前学校周边3家自习室空位靠微信群登记”，那么这3家自习室就是你的天然直接竞争方——他们已经掌控了存量座位。你不去帮他们引入新客流，还要从他们牙缝里抽佣，他们为什么选择把交易数据开放给你？更险恶的是，如果平台上线后验证了模式，这3家自习室完全可以联合做一个本地小程序，或直接开通如美团/大众点评的“自习室预订”功能，届时你没有任何差异。而且你没有提学校图书馆、考研教室这类免费替代项，它们的存在会直接冲击你的付费需求。
- 待验证：这3家自习室是否有官方微信群运营能力，或是否已开通自助预定工具；更大规模的竞品（如美团、大众点评）在学校所在城市是否已有自习室预订接口。

⑤【壁垒假设｜一般】
- 攻击：你未说明“拼团”之外的任何壁垒。“先做本校”意味着先发优势只覆盖单一学校极小半径。如果模式跑通，周边其他学校、其他付费自习室买一套第三方工具或用轻量自研就能复制该逻辑，你还剩什么？如果只是几个微信群的群主和信任关系，那这种关系不在你手里，在自习室老板手里。
- 待验证：你计划的“拼团模式”在备考生中的转介绍率假如能达到什么水平（例如裂变系数k=？），才足以形成本地无法复制的网络。

证据缺口：
- 三家自习室实际座位总数、月销量、空置率及单座运营成本。
- 该考点备考生的总数、来源结构（本校学生比例，是否包括往届/二战学生）。
- 120名受访学生的后续行为数据（他们是否有过付费买固定座的历史记录而非意愿）。
- 平台向自习室抽佣这一模式，B端是否愿意合作的访谈简报。
- 学生每月固定可支配金额及是否用于校外学习空间的预算。

必须回答的问题：
① 请项目方澄清：如果3家自习室已经完全满座，你的10%抽佣是从新增的收入中抽，还是从它们现有搬不动的收入池里抽？如果是后者，B端为什么不能直接屏蔽你？
② 请项目方出示：当初你访谈的120名学生所处的实际学习状态，比如多少人在使用付费自习室，多少人在图书馆抢固定座位，多少人的诉求是“随便坐下来学习”而非“预约”？
③ 请实测：当你上线小程序时，第一批愿意把座位和价格投放给你的B端自习室是哪家？他们愿意放弃自己微信群去换用一个抽佣系统的真实签字意向是什么？
④ 请计算：你抽佣10%，在向B端收钱时，是否要扣除给学生的300元全款作为流转？如果平台承担支付通道手续费和客服，那单笔毛利是多少？如果座位月租的流失率达到多少，平台会陷入负毛利？
⑤ 你所谓的“拼团”拼的是什么？是多人报名同一家自习室打折，还是多人合并订单抽佣？拼团失败后由谁承担损失？

修改方向：
- 必须先验证B端（自习室）的真实付费意愿，不能用C端访谈代替B端访谈。
- 必须搞清楚：300元/月是用户的预算，还是用户和自习室之间的最终成交价？平台抽佣的抽成基数与计费方式必须先定义清楚。
- 必须验证学生是否真会为“固定座位预约”支付超出目前市场价的价格，而不是简单表达“愿意尝试”。
- 必须先回答清楚，当三家自习室空位自己能卖完时，你的平台到底提供了什么不可替代的中介价值。
