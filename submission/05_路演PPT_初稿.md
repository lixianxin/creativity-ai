# 路演 PPT 初稿（10 页 · 现场讲故事，不是设计文档复述）

每页含：标题 / 版面要点 / 演讲备注。证据只用真实验证过的数字；不出现 RAG、LangChain 等术语和"首创/颠覆"类表述。

## P1 封面
- **版面**：作品名「创想∞ AI创业委员会」；副标题"先质疑，后肯定——12 位 AI 委员的创业评审系统"；一行真实项目输入示例。
- 演讲备注：一句话开场——"今天要演示的不是一个会夸人的 AI，而是一个敢说不的 AI 委员会。"

## P2 创业教育为什么需要"反方委员会"
- **版面**：左列现状（想法止步于自嗨、老师评审负荷重、口头鼓励多、致命问题发现晚）；右列后果（需求没验证就做、付费方说不清、比赛后项目死亡）。
- 数据口径：只说"评审资源稀缺、反馈滞后"，不编调研数字。
- 演讲备注：讲一个画面——学生路演那天才第一次被问"谁付钱"，已经晚了。

## P3 三委员会 + 12 Agent
- **版面**：一张结构图——专家委员会 8 官（用户/市场/竞品/产品/商业模式/财务/增长/风险）→ 对抗委员会 1 官（红队质疑官）→ 决策委员会 3 官（总指挥/评审官/路演答辩官）。
- 演讲备注：强调角色冲突是被设计出来的：专家负责分析，红队负责攻击，风险官有否决权，指挥官和评审官分权——一个系统里必须有人唱反调。

## P4 核心业务闭环
- **版面**：横向流水线：输入想法 → 8 专家并行尽调 → 红队五维质疑 → 风险红线把关 → 总指挥阶段结论 → 评审终审 → 路演问答 → 12 份报告。
- 标注：第一层 8 个 Agent **同时开工**。
- 演讲备注：用户只做一件事——提交想法；剩下的是委员会自己跑完。

## P5 红队质疑案例（全场最重要一页）
- **版面**：直接引用真实 Run 的两段攻击原文（打码排版成卡片）：
  - 付费假设："口头兴趣 ≠ 采购意愿——预算权、审批流程、立项记录全部为零"
  - 增长假设："没有冷启动路径，上线即静默；增长目标缺渠道×流量×转化率推导链"
- 底部一行：五维 = 需求/付费/竞争/增长/壁垒，逐维给出"待验证证据"。
- 演讲备注：评委可以现场扫二维码/看 Demo 里的原文——这不是模板话术，是针对这份项目原文生成的攻击。

## P6 风险红线案例
- **版面**：红线清单（备案/数据授权/合规/误导建议）+ 机制说明"一票否决由程序执行，不允许模型自己推翻"；展示终审页"系统规则强制"留痕截图位。
- 演讲备注：AI 最大的风险是它太会顺着人说——所以否决权写成系统规则，而不是提示词里的一句请求。

## P7 技术架构：为什么它"跑得稳、判得准"
- **版面**：三块，每块一句人话：
  1. **依赖图调度**：12 个 Agent 按依赖关系自动识别谁能并行、谁必须等待；
  2. **程序校验 + 自动返工**：每份输出先过确定性校验，不合格返工一次并留证；单个 Agent 失败会被隔离/降级，不拖垮全流程；
  3. **断点续跑**：中途中断可恢复，已完成的棒不重复花钱调用。
- 演讲备注：不堆术语，讲一句工程观——"LLM 是不受信任的执行者，程序负责最终约束。"

## P8 真实验收数据（只放有证据的）
- **版面**：四张小卡片：
  - 真实 API 全链路：12/12 Agent 成功（Run 可复查）
  - 8 委员真实并行；两次真实运行耗时 363.8s → 267.8s（注明"两次真实运行对比，非固定指标"）
  - 270 项离线自动化验收全绿
  - 真实故障链验证：Agent 失败 → 下游自动阻断/降级 → 恢复后续跑
- 演讲备注：主动说明 267.8s 只是两次运行的对比，我们不包装性能承诺——这句话本身就是工程严谨性的展示。

## P9 现场 Demo 引导
- **版面**：三个观看锚点（与 5 分钟视频一致）：①看 8 专家同时开跑；②看红队攻击原文；③看终审"暂缓通过"与 3 条可验证行动。
- 演讲备注：演示时请评委随便指定一个想法，现场跑（或播放预录真实 Run）；强调结论可能是"不通过"——系统诚实比系统乐观更有价值。

## P10 项目价值与愿景
- **版面**：三类用户价值——学生（提前经历严苛评审）、教师（12 维结构化初筛减负）、高校（双创课程的可复盘教学工具）；收尾句"在见投资人之前，先见你的 AI 委员会"。
- 演讲备注：不画大平台故事，落点在教学场景的真实闭环：每个想法都能低成本获得一次严格、诚实、可复盘的评审。
